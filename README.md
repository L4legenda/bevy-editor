# Bevy Editor

Встроенный **MCP-сервер** позволяет работать с открытой сценой из MCP-клиента: читать объекты, менять трансформации, добавлять модели и свет, получать снимок 3D-вида, сохранять и отменять правки. Подключение через stdio и Streamable HTTP описано в [инструкции MCP](docs/mcp.md).

Небольшой нативный 3D-редактор сцен для **Bevy 0.20.1**. Отдельный инструмент разработки с деревом сцены, инспектором, 3D-видом и каталогом моделей с отрендеренными миниатюрами.

## Запуск

Нужен Rust **1.97.1+** и совместимый с Bevy графический драйвер.

```sh
git clone git@github.com:L4legenda/bevy-editor.git
cd bevy-editor
./run-editor.sh
```

Скрипт собирает и запускает редактор; его можно вызывать из любого каталога. При первом запуске Cargo скачает зависимости и соберёт приложение. Прямой запуск через Cargo: `cargo run --locked`.

В Windows дважды щёлкните [run-editor.vbs](run-editor.vbs): менеджер проектов откроется без окна консоли. Файл запускает готовую сборку из `target/debug`; если её нет, скрыто собирает редактор через Cargo. Поддерживаются `run-editor.vbs --example` и путь к проекту в аргументе; `run-editor.cmd` оставлен как совместимый вход. Ошибки сборки сохраняются в `%LOCALAPPDATA%/BevyEditor/logs/launcher.log`, ошибки запуска — в `editor.log` в той же папке и показываются в диалоге. Для обновления готовой сборки после изменения кода выполните `cargo build --locked`, предварительно закрыв редактор.

В macOS можно дважды щёлкнуть [run-editor.command](run-editor.command) в Finder: откроется Terminal и запустится редактор. Файл автоматически подключает окружение Cargo из установки rustup.

Без аргументов сначала откроется **менеджер проектов**. В нём можно:

- создать проект из шаблона «Пустая 3D-сцена» или «Базовая 3D-сцена» с кубом, камерой и дневным светом;
- открыть папку через системный диалог или вставить путь к папке / файлу проекта;
- найти недавно открытый проект, добавить его в избранное и открыть двойным щелчком или Enter;
- убрать запись из списка, сохранив все файлы на диске.

Ctrl/Cmd+N открывает создание, Ctrl/Cmd+O — открытие проекта. Enter открывает найденный проект, Esc закрывает диалог или очищает поиск. ПКМ по карточке проекта открывает меню: открыть, добавить в избранное, показать папку или убрать запись из списка. Меню также открывается через Shift+F10 и закрывается по Esc или клику снаружи. После успешного запуска редактора менеджер проектов закрывается. При ошибке открытия он остаётся на экране.

Новый проект содержит JSON-файл **`project.bevyeditor`** с названием, относительной папкой ассетов, списком файлов сцен и каталогом моделей. Любой `.glb` — модель. Сцены хранятся в самостоятельных файлах `.scene`: каждый содержит ссылки на модели, их позиции, повороты и масштабы, камеры и освещение. Отдельная папка `levels` не нужна. Сцена подходит и для игровой локации, и для сборки персонажа. Проект можно перенести целиком в другую папку. Создание допускается только в новой или пустой папке и не перезаписывает существующие файлы. По умолчанию создаётся подпапка с названием проекта.

Недавние проекты хранятся отдельно от проекта: в macOS — `~/Library/Application Support/BevyEditor/recent-projects.json`, Windows — `%APPDATA%/BevyEditor/recent-projects.json`, Linux — `$XDG_CONFIG_HOME/bevy-editor/recent-projects.json` (по умолчанию `~/.config`).

Команда `./run-editor.sh --example` запускает встроенный пример из двух сцен и двух моделей. Его GLB созданы специально для этого репозитория; сторонние игровые ассеты не нужны. Перегенерация примера — `python examples/generate_assets.py`.

Для открытия сразу в редакторе передайте папку либо файл настроек:

```sh
./run-editor.sh path/to/my-project
./run-editor.sh path/to/project.bevyeditor
```

Прежние файлы `project.json` продолжают поддерживаться. Если в папке есть оба файла, используется `project.bevyeditor`. Относительный путь разрешается от каталога, из которого вызван скрипт. Справка: `./run-editor.sh --help`.

За основу можно взять [examples/project.json](examples/project.json). `asset_root` разрешается относительно файла проекта. В списке `scenes` достаточно ссылки `{"file": "scenes/workshop.scene"}`. Имя сцены, камеры и состав объектов находятся в самом `.scene`. Скопированный в папку ассетов файл `.scene` обнаруживается после обновления файлового менеджера. GLB независимо от папки отображается как модель и добавляется в сцену перетаскиванием; открытие `.scene` создаёт вкладку.

Прежние проекты с исходным GLB и JSON правок поддерживаются для совместимости. Тестовые файлы прежнего формата находятся в `tests/fixtures/legacy`. Встроенные примеры и новые проекты используют `.scene`.

Каталог содержит ссылки `asset` на GLB, подпись, категорию, признак `solid` и необязательный `preview_direction`. Последний позволяет развернуть превью настенных моделей. Миниатюры моделей и сцен создаются последовательно только для открытой папки или результатов поиска и остаются в памяти. Сцена показана из первой заданной камеры с текущими правками и добавленными моделями, включая несохранённые изменения в неактивных вкладках. Правки обновляют его автоматически; после внешних изменений на диске нажмите «Обновить». Исходные ассеты после рендера освобождаются; переход в другую папку отменяет неактуальное задание.

Нижний файловый менеджер по умолчанию свёрнут. Кнопка «Файловый менеджер» или Ctrl+Space открывает его с анимацией снизу; Esc и «Свернуть» закрывают. В нём доступны дерево папок `asset_root`, путь, переходы назад/вперёд/вверх и поиск внутри текущей папки и её подпапок. Отображаются обычные файлы с точными именами и расширениями, GLB-модели и изображения с превью. Для изображений показываются размеры в пикселях; полный путь и размер выбранного файла видны в нижней строке. Папки слева изначально свёрнуты, стрелки раскрывают и сворачивают ветки независимо от перехода между папками. Высоту панели можно менять перетаскиванием её верхней границы; выбранная высота сохраняется до закрытия приложения. Модели обнаруживаются автоматически, а настройки уже описанных элементов каталога сохраняются. Файлы `.scene` отображаются карточками «Сцена» и открываются для редактирования. GLB всегда отображается как модель. После добавления файлов на диске нажмите «Обновить».

Верхняя полоса содержит открытые сцены, модели и изображения. При запуске открывается первая сцена проекта; Ctrl+O показывает файловый менеджер. Выберите карточку сцены, чтобы открыть вкладку. Каждый файл `.scene` открывается в собственной вкладке. Между вкладками сохраняются несохранённые правки, история отмены и свободный ракурс. Маркер `(*)` сразу после названия вкладки отмечает несохранённые изменения, включая ввод в числовое поле до нажатия Enter; после сохранения или возврата к сохранённому состоянию он исчезает. Крестик закрывает вкладку, а после закрытия последней остаётся пустое рабочее пространство.

Файлы и папки можно перетаскивать в папки дерева, карточки папок, путь сверху или свободное место текущей папки. Это перемещает их на диске; ссылки в открытых и сохранённых сценах обновляются вместе с историей правок. Совпадение имён отменяет перемещение. Модели GLB, включая исходный GLB сцены, можно перетащить в 3D-вид. Во время перетаскивания модель с оригинальными материалами и непрозрачностью 80% следует за курсором, а метка и рамка основания показывают место установки на полу или поверхности другого объекта. Модель ставится основанием на поверхность, независимо от исходного центра GLB; привязка к сетке учитывается сразу. Отпускание мыши добавляет экземпляр в показанное место одним действием; Ctrl+Z отменяет добавление, Esc отменяет перетаскивание. Если геометрия ещё загружается, место фиксируется при отпускании, а экземпляр добавляется после загрузки. Отмена, смена сцены и потеря фокуса убирают временное превью без изменения документа. Клик по карточке модели открывает вкладку просмотра; клик по карточке сцены открывает вкладку редактирования. Вкладки моделей и сцен находятся в общей панели. Повторное открытие выбирает существующую вкладку, ракурс модели сохраняется при переключении.

Просмотр моделей использует Small Studio, тёплый направленный свет с тенями, ACES и размытый фон HDRI. Яркость и поворот окружения, экспозиция, размытие и яркость фона, сила и направление основного света настраиваются в правой панели. Параметры общие для вкладок моделей и сохраняются в `asset_root/.bevy-editor/model-preview.json`.

Перемещения сохраняются в `asset_root/.bevy-editor-asset-moves.json`, поэтому старые пути проекта продолжают работать после перезапуска. Этот файл нужно хранить вместе с ассетами. Если перенос отдельного файла нарушил бы относительные ссылки glTF на текстуры или буферы, редактор отменит его: переносите модель вместе с зависимостями в общей папке.

Изображения PNG, JPEG, WebP, BMP, TGA, GIF, ICO и SVG отображаются миниатюрами; шахматный фон показывает прозрачность. Папки, модели, сцены, изображения и остальные файлы отображаются вместе в общем списке. Поиск работает внутри текущей папки и её подпапок. Двойной щелчок по карточке открывает изображение во вкладке верхней панели рядом со сценами и моделями. Масштаб и положение картинки сохраняются при переключении вкладок; файловый менеджер остаётся доступен. Кнопки и ← / → переключают картинки из текущей папки или результатов поиска. Колесо меняет масштаб вокруг курсора, перетаскивание перемещает увеличенную картинку. «Вписать» (F / 0) подбирает размер окна, «1:1» (1) показывает пиксели в исходном масштабе с учётом DPI; двойной клик переключает эти режимы. Кнопка фона (B) меняет шахматный, тёмный и светлый фон. Ctrl+W или крестик на вкладке закрывает изображение, сохраняя остальные вкладки, папку, поиск и прокрутку файлового менеджера. Esc сворачивает файловый менеджер. Изображения загружаются в фоне; повреждённый файл можно пропустить или загрузить повторно. Для GIF показывается первый кадр, для больших файлов размер текстуры просмотра ограничен 4096 px по каждой стороне; размеры в подписи относятся к оригиналу.

По центру панели изображения находится список «Просмотр / Редактирование». Новые вкладки открываются в режиме просмотра. Редактирование использует ядро PhotoCraft: кисть / карандаш (B), ластик (E), заливка (G), пипетка (I), перемещение слоя (V), рука (H / Пробел), выбор цвета HSV / HEX и палитру. Справа доступны создание, дублирование, переименование, видимость, порядок и непрозрачность слоёв. ПКМ по кнопке рисования открывает выбор кисти или карандаша; Shift+B переключает их, B возвращает последний выбранный инструмент. Кисть рисует со сглаживанием, карандаш рисует по пиксельной сетке без сглаживания, начиная с 1 px. Размеры кисти и карандаша запоминаются отдельно. Ctrl+Z отменяет действие; Ctrl+Shift+Z / Ctrl+Y повторяет. При первом включении редактирования рядом создаётся одноимённый `.pcraft` с растровыми слоями. Ctrl+S сохраняет слои и обновляет исходное изображение в прежнем формате. Повторное редактирование оригинала загружает слои из `.pcraft`. Закрытие вкладки или редактора с несохранёнными правками предлагает сохранить, продолжить без сохранения или отменить закрытие. Начальный набор поддерживает 8-битные RGB-изображения PNG, JPEG, WebP, BMP, TGA и ICO до 16 Мп и 64 растровых слоёв. Встроенные библиотеки и лицензии перечислены в `ATTRIBUTION.md`.

## Управление

Менеджер проектов и редактор используют общую верхнюю панель без системного заголовка окна. Перетаскивайте свободную область панели, дважды щёлкните её для разворачивания или восстановления размера; кнопки справа сворачивают, разворачивают и закрывают окно. Размер окна меняется за края и углы. Закрытие редактора по-прежнему предлагает сохранить несохранённые сцены.

Картинки можно перетащить из Проводника прямо в файловый менеджер — по одной или несколько сразу. Импорт создаёт копии в текущей папке либо в папке под курсором (дерево, карточка или путь сверху), а миниатюры появляются автоматически. Совпадающие имена получают суффикс «(2)», «(3)» и далее. ПКМ открывает меню «Создать папку»: на свободном месте — для текущей папки, на папке — внутри неё. Введите название и нажмите «Создать» или Enter; Esc отменяет ввод. Ctrl+Shift+N сразу открывает создание папки. Ошибки имени и совпадение с существующим файлом показываются прямо в диалоге.

| Действие | Управление |
| --- | --- |
| Открыть сцену | Ctrl+O, затем карточка сцены в файловом менеджере |
| Закрыть вкладку сцены | × во вкладке / Ctrl+W |
| Выбор | Режим со стрелкой (Q), затем клик в 3D-виде или дереве |
| Выбор и преобразование (по умолчанию) | Q — выбор объектов, стрелки и площадки для перемещения, дуги и внешний круг для поворота |
| Перемещение / вращение / масштаб | W / E / R и перетаскивание оси |
| Пространство координат | Куб «Использовать локальное пространство» в верхней панели; по умолчанию глобальное. В локальном режиме оси следуют повороту объекта, координаты инспектора задаются относительно родителя |
| Привязка | Кнопка в панели — 0,25 м / 15° / 0,1 |
| Полёт | ПКМ + WASD, Q/E; Shift ускоряет |
| Орбита / панорама | Alt + ЛКМ / средняя кнопка |
| Приближение / фокус | Колесо / точка на цифровом блоке (Num .) — плавный перелёт к объекту; Esc или ручное управление прерывают анимацию |
| Сброс выбранного объекта | Alt+Q — всё; Alt+W — позиция; Alt+E — поворот; Alt+R — масштаб |
| Числовое поле | Enter, Tab или переход в другое поле применяют число; Esc отменяет ввод |
| Предпросмотр камеры | Выбор камеры в дереве — живое превью кадра 16:9 и границы обзора в сцене |
| Управление камерой | «Управление камерой»; Esc / «Выйти из камеры» возвращает свободный вид |
| Движение камеры из её вида | ПКМ + WASD, Q/E; мышь поворачивает, Shift ускоряет; средняя кнопка — панорама |
| Кадрирование из камеры | Колесо: перемещение вперёд/назад; у ортографической камеры — высота кадра |
| Перенос камеры в текущий вид | «Из вида» |
| Просмотр модели | Нажать карточку GLB, чтобы открыть вкладку; ЛКМ / ПКМ — вращение, СКМ — панорама, колесо — приближение, F — вписать, Esc / Ctrl+W — закрыть вкладку |
| Окружение просмотра модели | Справа: HDRI, яркость и поворот, экспозиция, ACES / AgX / Neutral, фон и направленный свет |
| Добавление модели | Перетащить карточку GLB в 3D-вид |
| Перемещение файлов и папок | Перетащить в папку дерева, карточку папки или путь сверху |
| Дублирование / удаление добавленной модели | Ctrl+D / Delete |
| Сохранение / отмена / повтор | Ctrl+S / Ctrl+Z / Ctrl+Y |
| Файловый менеджер | Нижняя кнопка / Ctrl+Space; Esc закрывает |
| Импорт изображений | Перетащить файлы из Проводника в файловый менеджер или на нужную папку |
| Новая папка | ПКМ → «Создать папку» / Ctrl+Shift+N; Enter создаёт, Esc отменяет |

На macOS для открытия и закрытия вкладок, сохранения, отмены, повтора и дублирования можно использовать Cmd вместо Ctrl. Файловый менеджер открывается через Ctrl+Space. Подсказки при наведении и клавиатурном фокусе объясняют действия и сочетания клавиш. Недоступные кнопки приглушены и пропускаются при переходе через Tab. Инспектор прокручивается, если все параметры не помещаются по высоте.

Ширина всех меню справа меняется перетаскиванием левой границы панели. Разделитель между деревом сцены и инспектором меняет их высоту. Выбранные размеры сохраняются при переключении объектов и сцен; после временного уменьшения окна они восстанавливаются. Esc отменяет перетаскивание. Разделители также доступны через Tab: стрелки меняют размер, Shift задаёт меньший шаг, Home возвращает автоматический размер.

Выбранный объект выделяется тонкими оранжевыми уголками по границам всей модели в 3D-виде. Объёмная рамка следует повороту и масштабу объекта и видна сквозь остальные объекты. Цветные оси позволяют перемещать, вращать и масштабировать выделение. По умолчанию включён режим со стрелкой (Q), в котором доступны выбор объектов, перемещение и поворот. Масштабирование доступно только отдельным инструментом R. В режимах W/E/R клики в сцене и дереве сохраняют текущее выделение; для выбора другого объекта вернитесь к Q. У стрелок перемещения заполненные наконечники, у масштаба — заполненные объёмные кубики; у всех трёх инструментов есть белая точка в центре. Манипулятор вращения имеет постоянный размер на экране: три цветные передние полудуги и тонкое серое кольцо для вращения в плоскости экрана. При захвате форма дуг сохраняется, активная ось подсвечивается. В миниатюрах и превью камер уголки не отображаются.

«+ Свет» открывает меню создания: точечный источник, прожектор, солнце и прямоугольная панель. Есть отдельные пресеты лампочки, свечи, софтбокса, неона, прожектора, солнца и луны, а также схемы дневного света, тёплого интерьера, ночи и студии. Схема заменяет только добавленные в редакторе светильники и общие настройки освещения одним отменяемым действием. Источники выбираются в дереве или по значку в 3D-виде; их можно перемещать, поворачивать, переименовывать, дублировать и отключать. Цвет источника, фонового света и тумана выбирается на двумерной палитре насыщенности и яркости; полоса под ней меняет оттенок. Рядом показаны образец и HEX-код цвета. Температура в Кельвинах, мощность в люменах (для солнца — люксы), яркость фона, экспозиция, дальность, радиус, углы прожектора и размеры панели меняются ползунками с немедленным результатом в сцене. Одно перетаскивание отменяется целиком через Ctrl+Z, а Esc возвращает значение до начала перетаскивания. Расширенные параметры теней раскрываются отдельно. Панели в текущей версии Bevy не отбрасывают тени.

Строка «Освещение сцены» в дереве открывает фоновый свет, экспозицию EV100, тональное отображение, туман, качество теней и переключатель источников из исходного GLB. Эти настройки, добавленные светильники и история отмены независимы для каждой вкладки. Превью камер, миниатюры сцен и сохранённые документы учитывают изменения; Esc закрывает меню, Ctrl+Z отменяет правку.

В разделе HDRI выбирается одно из десяти окружений Poly Haven: студии, склад, интерьер, облачное небо, закаты, лес или ночь. Выбранная панорама видна вдали за сценой, освещает объекты и отражается на материалах с учётом их шероховатости. Яркость HDRI и поворот вокруг вертикальной оси меняются ползунками; фон поворачивается вместе с освещением. Переключатель «Панорама на фоне» позволяет скрыть картинку, сохранив свет и отражения. «Выкл.» отключает окружение, сохраняя значения ползунков. Настройки сохраняются в сцене, поддерживают отмену и используются в превью камеры и миниатюрах сцен. Карты встроены в приложение, загружаются асинхронно и разделяются между камерами; копировать их в каждый проект не требуется. Исходные панорамы и подготовленные карты имеют [лицензию CC0](assets/hdri/LICENSE.txt). Повторная подготовка: `python tools/prepare_hdri.py --source path/to/hdri` (нужны `numpy` и `zstandard`).

Кнопка «Скачать HDRI…» в настройках освещения открывает каталоги [Poly Haven](https://polyhaven.com/hdris) и [ambientCG](https://ambientcg.com/list?type=HDRI). В окне есть превью, поиск по названию и тегам, страницы каталога и выбор 1K/2K/4K. «Скачать» показывает ход загрузки и позволяет её отменить; после завершения карта попадает во вкладку «Скачанные» и список окружений в инспекторе. Кнопка «Использовать» применяет её к сцене с поддержкой отмены. HDR и EXR из ZIP ambientCG подготавливаются для фона, освещения и отражений в фоне; Python и ручная конвертация не нужны. Панорамы, источник и лицензия хранятся внутри `asset_root/hdri`, поэтому скачанные окружения работают без интернета и переносятся вместе с проектом. Каталоги и превью кешируются в `asset_root/.bevy-editor/hdri-catalog`; «Обновить» запрашивает свежие данные. Выбор окружения, его поворот, яркость и видимость панорамы сохраняются в сцене.

Числовые поля принимают точку и запятую как десятичный разделитель. Ошибочное значение остаётся в поле с подсветкой и объяснением; его нужно исправить или отменить через Esc перед сохранением, сменой сцены и закрытием окна.

История хранит до 64 действий. Незавершённое перетаскивание отменяется по Esc. При закрытии изменённой вкладки или окна с несохранёнными изменениями появляется выбор: сохранить, продолжить без сохранения или отменить переход. Ошибка сохранения оставляет диалог открытым и сохраняет правки в памяти. При выходе проверяются все открытые сцены, включая неактивные вкладки. Запуск игры требует сохранить изменения. Кнопка «Играть» появляется, если у сцены задан `play` — программа и массив аргументов, без командной оболочки. `program: null` запускает текущий исполняемый файл. Рабочий каталог и относительный путь программы следуют правилам `std::process::Command`.

Движение из вида камеры меняет её позу в текущей сцене. Один жест навигации отменяется целиком через Ctrl+Z; Ctrl+S записывает текущий ракурс в файл. Выход из вида камеры сохраняет её изменения в памяти и возвращает прежний свободный вид редактора. Превью и вид из камеры используют одинаковый кадр 16:9.

## Подключение к игре

Добавьте репозиторий как Git submodule и подключите пакет по локальному пути:

```sh
git submodule add git@github.com:L4legenda/bevy-editor.git modules/bevy-editor
```

```toml
[features]
editor = ["bevy-editor/editor"]

[dependencies]
bevy-editor = { path = "modules/bevy-editor", default-features = false }
```

Без фичи `editor` доступны формат уровней и функции инстанцирования. UI, миниатюры и управление камерой подключаются только к инструменту разработки. Для клонирования игры используйте `git clone --recurse-submodules` или `git submodule update --init --recursive`.

В отдельном исполняемом файле редактора:

```rust,no_run
use bevy_editor::{EditorProject, create_app};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let project = EditorProject::load("project.json")?;
    create_app(project)?.run();
    Ok(())
}
```

`EditorProject` также можно собрать в Rust. `scene_setup` и `camera_setup` позволяют применить материалы, свет и эффекты игры. Свои плагины добавляются в возвращённый `App` до `run()`. Для полностью своего приложения доступен `EditorPlugin::new(project)`; добавляйте его после `DefaultPlugins`, отключив стандартное закрытие окна через `WindowPlugin::close_when_requested`.

В собственном нативном приложении добавьте `AssetRedirectPlugin::new(asset_root)?` **до** `DefaultPlugins`, чтобы загрузка через `AssetServer` поддерживала сохранённые перемещения. `create_app` уже подключает этот плагин. Обработчики `scene_setup` и `camera_setup` получают исходные логические пути сцен.

## Формат сцены и runtime

Файл `.scene` использует JSON. Поле `scene` содержит название и определения камер; остальные поля описывают содержимое:

* `scene` — `label` и список `cameras` с ID, подписью, проекцией и исходной позой;

* `nodes` — поддерживается только для совместимости с правками прежних GLB-сцен; новые сцены используют `models`;
* `cameras` — позы и объективы камер по стабильным ID;
* `models` — ID экземпляра, относительный путь общего GLB, поза и необязательный локальный AABB для коллизии.
* `lights` — источники света со стабильными ID, типом, позой, цветом, мощностью и настройками теней;
* `lighting` — общие настройки освещения и камеры. Отсутствующее поле сохраняет исходное освещение хоста.

Сохранение проверяет данные и заменяет файл через временный файл в том же каталоге. Дублирование создаёт новый ID и сохраняет ссылку на тот же ассет. Меши и текстуры загружаются через общий `AssetServer`.

```rust,no_run
use std::path::Path;
use bevy_editor::LevelEdits;

let edits = LevelEdits::<String>::read(Path::new("assets"), "scenes/workshop.scene");
```

`LevelEdits<K>` поддерживает и сериализуемый enum камер игры. Его snake_case ключи совместимы со строковыми ID редактора. `runtime::imported_nodes` находит редактируемые объекты, `runtime::spawn_model` создаёт экземпляры. Runtime игры применяет мировую позу узла через `GlobalTransform::reparented_to` и использует `anchor` / `seat_yaw` для связанных игровых точек. Система коллизий и игровой запуск принадлежат хосту; `solid` сохраняет геометрические границы модели для его использования.

Для применения света в игре подключите фичу `lighting` у зависимости `bevy-editor`. `lighting::spawn_light` / `runtime::spawn_lights` создают сохранённые источники; `lighting::apply_camera_lighting` применяет окружение к игровой камере после настроек хоста, а `lighting::apply_imported_light` — переключатели к исходным светильникам. DTO и чтение JSON доступны без этой фичи. В `Clinic-of-desires-bevy` сохранённое освещение уже подключено к обычному запуску игры.

Для встроенных HDRI добавьте `bevy_editor::HdriPlugin` после `DefaultPlugins`, затем применяйте сохранённый `SceneLighting` через `apply_camera_lighting`. Редактор подключает плагин автоматически. В редакторе для сцен без сохранённых настроек освещения по умолчанию включено HDRI «Облачно» с панорамой на фоне, тёплым заполняющим светом и мягкой светлой картинкой (экспозиция 8 EV100, Reinhard Luminance, яркость HDRI 1300). Новые проекты сохраняют эти настройки в стартовой сцене и используют HDRI без дополнительного яркого солнца. Сохранённые окружения и явное «Выкл.» имеют приоритет. При чтении старых DTO в игре прежняя семантика отсутствующих настроек сохраняется.

Текущая область редактирования — расстановка объектов и камер в GLB-сценах. Пересборка геометрии, редактирование материалов, скриптов и анимаций выполняются в исходных инструментах.

## Готовые сборки Windows

GitHub Actions автоматически собирает `bevy-editor.exe` для Windows x64 в режиме `--release`:

| Push в ветку | Публикация на GitHub | Пример тега |
| --- | --- | --- |
| `main` | Обычный Release с пометкой Latest | `v0.1.0+build.42.1.abcdef12` |
| `develop` | Pre-release с отдельным тегом | `develop-42.1-abcdef12` |

В тег входят номер запуска workflow, номер попытки и первые восемь символов коммита. Для `main` добавляется версия из `Cargo.toml`. Повторный запуск создаёт новый тег; предыдущие сборки сохраняются. Сборки `develop` не получают пометку Latest.

Скачайте `bevy-editor.exe` из [Releases](https://github.com/L4legenda/bevy-editor/releases) и запустите его: откроется менеджер проектов. Rust и Cargo для готовой сборки не нужны. Шрифт, иконки и HDRI встроены в приложение. Существующий проект можно открыть командой `bevy-editor.exe --project PATH`.

Workflow [Windows releases](.github/workflows/windows-release.yml) должен быть в обеих ветках. Он также поддерживает ручной запуск через **Actions → Windows releases → Run workflow** для `main` и `develop`. Публикация использует встроенный `GITHUB_TOKEN` с разрешением `contents: write`; отдельный секрет не нужен. Версия Rust берётся из `package.rust-version` в `Cargo.toml`.

## Проверки

```sh
cargo fmt --check
cargo test --locked
cargo test --locked --no-default-features
```

Тесты проверяют перезапись и совместимость документов с типизированными камерами, отклонение некорректных ссылок, общие ассеты при дублировании, историю изменений, ограничения трансформаций и переход между сценами с разным числом объектов. Тестовый код компилируется только в тестах.

Встроенный шрифт Liberation Sans распространяется по [SIL Open Font License](assets/font/OFL.txt).

SVG-иконки интерфейса — [Lucide](https://lucide.dev/icons), с [лицензиями ISC и MIT](assets/icons/lucide/LICENSE). Исходники находятся в `assets/icons/lucide/` и встроены в редактор; чёткие текстуры создаются и кэшируются под масштаб экрана.
