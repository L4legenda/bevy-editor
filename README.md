# Bevy Editor

Встроенный **MCP-сервер** позволяет работать с открытой сценой из MCP-клиента: читать объекты, менять трансформации, добавлять модели и свет, получать снимок 3D-вида, сохранять и отменять правки. Подключение через stdio и Streamable HTTP описано в [инструкции MCP](docs/mcp.md).

Небольшой нативный 3D-редактор сцен для **Bevy 0.20.1**. Отдельный инструмент разработки с деревом сцены, инспектором, 3D-видом и каталогом моделей с отрендеренными миниатюрами.

Для GLB-моделей доступна **UV-развёртка** с быстрым предпросмотром xatlas, автоматической развёрткой PartUV и отдельным уплотнением островов. Кисть и локальная модель DA Wand помогают выбрать участки, где лучше избегать швов. Карта растяжения показывает искажения на модели и в атласе. Результат можно отменить или сохранить в GLB. [Работа с UV](docs/uv-workspace.md)

## Запуск

Нужен Rust **1.97.1+** и совместимый с Bevy графический драйвер.

```sh
git clone git@github.com:L4legenda/bevy-editor.git
cd bevy-editor
./run-editor.sh
```

Скрипт собирает и запускает редактор; его можно вызывать из любого каталога. При первом запуске Cargo скачает зависимости и соберёт приложение. Прямой запуск через Cargo: `cargo run --locked`.

В Windows дважды щёлкните [run-editor.vbs](run-editor.vbs): менеджер проектов откроется без окна консоли. Перед запуском Cargo скрыто проверяет актуальность сборки в `target/debug` и при необходимости пересобирает редактор, в том числе после `git pull`. Первая сборка и сборка после крупных обновлений могут занять несколько минут. Для открытия проекта передайте путь к нему в аргументе; `run-editor.cmd` показывает ход проверки и сборки прямо в консоли, включая ожидание блокировки Cargo и ошибки компиляции; после успешного запуска консоль закрывается. Если исходники не менялись, повторной компиляции не будет. Ошибки сборки сохраняются в `%LOCALAPPDATA%/BevyEditor/logs/launcher.log`, ошибки запуска — в `editor.log` в той же папке и показываются в диалоге. Перед обновлением сборки закройте редактор.

При запуске из исходников `run-editor.vbs` и `run-editor.cmd` теперь также проверяют
компонент 3D-генерации на компьютерах с драйвером NVIDIA. `tools/build-editor.ps1`
собирает `bevy-hunyuan.exe` и подготавливает его CUDA-библиотеки рядом с редактором
в `target/debug`; после `git pull` компонент проверяется на актуальность вместе
с основным приложением. Первая подготовка может скачать CUDA 12.8.1 и занять
несколько минут. Веса нейросети при этом не загружаются в память: модель включается
кнопкой в редакторе. Для обычной сборки без этой подготовки можно задать
`BEVY_EDITOR_PREPARE_3D=0`; `1` принудительно включает подготовку. При прямом
`cargo run` компонент можно подготовить командой
`./tools/build-hunyuan.ps1 -Destination ./target/debug`.

Windows-запуски используют `tools/cargo.ps1` и небольшую Rust-утилиту `tools/cargo-cache`
для блокировки одновременных сборок и учёта артефактов. Python для этого не нужен.
Обёртка автоматически собирает утилиту отдельно от Bevy и проверяет её актуальность.
Для сборок и тестов через эту обёртку используйте:

```powershell
.\tools\cargo.ps1 build --locked --bin bevy-editor
.\tools\cargo.ps1 test --locked
.\tools\cargo.ps1 check --locked
```

Сборка и запуск только обновляют список артефактов в `target/.bevy-editor-cache.json`.
Автоматической очистки и ограничения размера `target` нет.

Для ручной очистки дважды щёлкните **[clean-cache.cmd](clean-cache.cmd)** рядом с
`run-editor.cmd`. Скрипт выполняет `cargo clean` и полностью удаляет содержимое `target`,
включая готовый редактор, зависимости и временные результаты проверок. Следующий запуск
заново соберёт приложение. Исходники и проекты вне `target` сохраняются.
Перед очисткой закройте редактор и дождитесь завершения сборок. Скрипт проверяет общую
блокировку сборки и запущенные программы из `target`; ссылки и junction вместо `target`
не допускаются. Из PowerShell ту же очистку можно вызвать командой `./tools/cargo.ps1 clean`.

В macOS можно дважды щёлкнуть [run-editor.command](run-editor.command) в Finder: откроется Terminal и запустится редактор. Файл автоматически подключает окружение Cargo из установки rustup.

Без аргументов сначала откроется **менеджер проектов**. В нём можно:

- создать проект из шаблона «Пустая 3D-сцена» или «Базовая 3D-сцена» с кубом, камерой и дневным светом;
- открыть папку через системный диалог или вставить путь к папке / файлу проекта;
- найти недавно открытый проект, добавить его в избранное и открыть двойным щелчком или Enter;
- убрать запись из списка, сохранив все файлы на диске.

Ctrl/Cmd+N открывает создание, Ctrl/Cmd+O — открытие проекта. Enter открывает найденный проект, Esc закрывает диалог или очищает поиск. ПКМ по карточке проекта открывает меню: открыть, добавить в избранное, показать папку или убрать запись из списка. Меню также открывается через Shift+F10 и закрывается по Esc или клику снаружи. После успешного запуска редактора менеджер проектов закрывается. При ошибке открытия он остаётся на экране.

Новый проект содержит JSON-файл **`project.bevyeditor`** с названием, относительной папкой ассетов, списком файлов сцен и каталогом моделей. `.glb` и `.fbx` — 3D-модели. Сцены хранятся в самостоятельных файлах `.scene`: каждый содержит ссылки на модели, их позиции, повороты и масштабы, камеры и освещение. Отдельная папка `levels` не нужна. Сцена подходит и для игровой локации, и для сборки персонажа. Проект можно перенести целиком в другую папку. Создание допускается только в новой или пустой папке и не перезаписывает существующие файлы. По умолчанию создаётся подпапка с названием проекта.

Недавние проекты хранятся отдельно от проекта: в macOS — `~/Library/Application Support/BevyEditor/recent-projects.json`, Windows — `%APPDATA%/BevyEditor/recent-projects.json`, Linux — `$XDG_CONFIG_HOME/bevy-editor/recent-projects.json` (по умолчанию `~/.config`).

Для открытия сразу в редакторе передайте папку либо файл настроек:

```sh
./run-editor.sh path/to/my-project
./run-editor.sh path/to/project.bevyeditor
```

Прежние файлы `project.json` продолжают поддерживаться. Если в папке есть оба файла, используется `project.bevyeditor`. Относительный путь разрешается от каталога, из которого вызван скрипт. Справка: `./run-editor.sh --help`.

Создайте собственный проект через менеджер проектов. `asset_root` разрешается относительно файла `project.bevyeditor`. В списке `scenes` достаточно ссылки `{"file": "scenes/main.scene"}`. Имя сцены, камеры и состав объектов находятся в самом `.scene`. Скопированный в папку ассетов файл `.scene` обнаруживается после обновления файлового менеджера. GLB и FBX отображаются как модели и добавляются в сцену перетаскиванием; открытие `.scene` создаёт вкладку.

FBX можно перетащить с диска в файловый менеджер или скопировать в папку ассетов и нажать «Обновить». Встроенный загрузчик ufbx читает бинарные и ASCII FBX. Для статических мешей он сохраняет иерархию, размеры, первую UV-карту и назначения материалов. Поддерживаются базовые PBR-свойства, встроенные и относительные текстуры цвета, нормалей и свечения. При перетаскивании FBX редактор копирует доступные текстуры из папки модели и её подпапок по их относительным путям. Совпадающие текстуры используются повторно. При конфликте имён редактор сохраняет файл проекта и показывает сообщение. Для ссылок вида `../textures` сохраните такое же расположение папок в проекте. Сцена сохраняет ссылку на исходный файл и размещение экземпляра. Вкладка FBX предназначена для просмотра статической геометрии, а редактор мешей, UV и рисование работают с GLB. Скелетные модели отображаются в исходной позе. [Загрузчик ufbx](https://github.com/ufbx/ufbx-rust)

Прежние проекты с исходным GLB и JSON правок поддерживаются для совместимости. Тестовые файлы прежнего формата находятся в `tests/fixtures/legacy`. Новые проекты используют `.scene`. При сохранении сцены записывается версионируемый формат с постоянными ID и таблицей ресурсов; прежние `.scene` читаются и мигрируют при сохранении. Библиотека формата также поддерживает иерархию, вложенные сцены и бинарный `.sceneb`; текущие инструменты редактора работают с плоскими моделями, камерами и светом. [Спецификация и команды](docs/scene-format.md), [проверка TSCN и измерения](docs/scene-format-audit.md).

Каталог содержит ссылки `asset` на GLB или FBX, подпись, категорию, признак `solid` и необязательный `preview_direction`. Последний позволяет развернуть превью настенных моделей. Миниатюры моделей и сцен создаются последовательно только для открытой папки или результатов поиска и остаются в памяти. Модели показаны с окружением, экспозицией и тональным отображением активной сцены, без дополнительного студийного пола; при отсутствии сцены используется стандартное окружение редактора. Изменение этих настроек или перезагрузка модели обновляет карточки автоматически. Сцена показана из первой заданной камеры с текущими правками и добавленными моделями, включая несохранённые изменения в неактивных вкладках. Правки обновляют её автоматически; после внешних изменений на диске нажмите «Обновить». Исходные ассеты после рендера освобождаются; переход в другую папку отменяет неактуальное задание.

Нижний файловый менеджер по умолчанию свёрнут. Кнопка «Файловый менеджер» или Ctrl+Space открывает его с анимацией снизу; Esc и «Свернуть» закрывают. В нём доступны дерево папок `asset_root`, путь, переходы назад/вперёд/вверх и поиск внутри текущей папки и её подпапок. Файловый менеджер показывает имена и расширения файлов, а для моделей GLB, FBX и изображений также строит превью. Для изображений показываются размеры в пикселях; полный путь и размер выбранного файла видны в нижней строке. Папки слева изначально свёрнуты, стрелки раскрывают и сворачивают ветки независимо от перехода между папками. Высоту панели можно менять перетаскиванием её верхней границы; выбранная высота сохраняется до закрытия приложения. Модели обнаруживаются автоматически, а настройки уже описанных элементов каталога сохраняются. Файлы `.scene` отображаются карточками «Сцена» и открываются для редактирования. После добавления файлов на диске нажмите «Обновить».

Верхняя полоса содержит открытые сцены, модели и изображения. При запуске открывается первая сцена проекта; Ctrl+O показывает файловый менеджер. Выберите карточку сцены, чтобы открыть вкладку. Каждый файл `.scene` открывается в собственной вкладке. Между вкладками сохраняются несохранённые правки, история отмены и свободный ракурс. Маркер `(*)` сразу после названия вкладки отмечает несохранённые изменения, включая ввод в числовое поле до нажатия Enter; после сохранения или возврата к сохранённому состоянию он исчезает. Крестик закрывает вкладку, а после закрытия последней остаётся пустое рабочее пространство.

Файлы и папки можно перетаскивать в папки дерева, карточки папок, путь сверху или свободное место текущей папки. Это перемещает их на диске; ссылки в открытых и сохранённых сценах обновляются вместе с историей правок. Совпадение имён отменяет перемещение. Модели GLB и FBX можно перетащить в 3D-вид. Во время перетаскивания модель с оригинальными материалами и непрозрачностью 80% следует за курсором, а метка и рамка основания показывают место установки на полу или поверхности другого объекта. Модель ставится основанием на поверхность, независимо от исходного центра модели; привязка к сетке учитывается сразу. Отпускание мыши добавляет экземпляр в показанное место одним действием; Ctrl+Z отменяет добавление, Esc отменяет перетаскивание. Если геометрия ещё загружается, место фиксируется при отпускании, а экземпляр добавляется после загрузки. Отмена, смена сцены и потеря фокуса убирают временное превью без изменения документа. Двойной щелчок по карточке модели открывает вкладку просмотра. Двойной щелчок по карточке сцены открывает вкладку редактирования. Вкладки моделей и сцен находятся в общей панели. Повторное открытие выбирает существующую вкладку, ракурс модели сохраняется при переключении.

Модель открывается в таком же рабочем 3D-виде, как сцена: общая мировая сетка, цветные оси, угловое выделение, заполненные стрелки и площадки манипулятора. По умолчанию используются те же HDRI «Облачно», тёплый фоновый свет, экспозиция 8 EV100 и Reinhard Luminance, что у новой сцены; дополнительный студийный направленный свет выключен. Окружение, экспозиция, фон и дополнительный свет настраиваются в правой панели и сохраняются отдельно от GLB в `asset_root/.bevy-editor/model-preview.json`. Старый студийный профиль при переходе на новый рабочий вид заменяется настройками по умолчанию в памяти; файл обновляется при следующем изменении параметров.

Справа сверху в открытой модели находится переключатель **«Объект / Редактирование»**. Новая вкладка начинает с режима «Объект»: ЛКМ выбирает объект, Shift добавляет его к выделению. Общая верхняя панель со значками выбора, перемещения, поворота и масштаба управляет активной сценой или открытой моделью; рядом находятся локальные оси и привязка. В модели доступны точные трансформации G/R/S. Имя, мировые координаты, углы в градусах и масштаб меняются в инспекторе. Доступны дублирование, объединение объектов, скрытие, зеркальное отражение, применение поворота/масштаба и перенос центра к геометрии. Дерево справа показывает отдельные меши GLB.

В режиме **«Редактирование»** кнопки 1/2/3 выбирают вершины, рёбра и грани активного объекта. Есть рамка выделения, выбор связанной геометрии, расширение/сужение выделения, рентген, пропорциональные трансформации, выдавливание, inset, подразделение, разрез петли по четырёхугольникам, сквозной нож, фаска вершин, триангуляция, объединение совместимых треугольников в четырёхугольники, растворение рёбер, заполнение отверстий, слияние вершин, отделение граней, сглаживание и нормали. Куб, сфера, плоскость и цилиндр добавляются через «Добавить…» / Shift+A. Имеющиеся UV и цвета сохраняются по углам полигонов; доступны простые проекции UV кубом и сферой. GLB хранит треугольники, поэтому для работы с петлями сначала выделите область и нажмите Alt+J.

В инструменте с курсором (Q) перетаскивание ЛКМ выделяет область рамкой — в сцене, в режиме объекта модели и при редактировании вершин, рёбер и граней. Короткое нажатие сохраняет обычный выбор щелчком; захват манипулятора по-прежнему запускает преобразование. Shift добавляет к выделению, Ctrl исключает, Esc отменяет рамку. В сцене манипуляторы перемещают, вращают и масштабируют всю выбранную группу относительно активного объекта; дублирование и удаление применяются ко всей группе, а поля инспектора относятся к активному объекту. В модели X-Ray позволяет включать скрытые элементы в рамку; клавиша B также остаётся доступной.

Выделение модели показано голубым цветом с тёмной окантовкой: вершины имеют заполненные маркеры, рёбра — утолщённые линии, грани — цветную заливку. Вокруг одной выбранной вершины видно кольцо, даже когда её перекрывает центр манипулятора. Подпись в 3D-виде и инспектор показывают тип элементов, число выбранных из общего количества и имя объекта; одна грань считается одной гранью, а не числом её вершин.

Кнопка **X-Ray** в верхней панели модели или **Alt+Z** включает полупрозрачный показ поверхности и сквозную сетку в режимах «Объект» и «Редактирование». Вершины, рёбра и центры граней доступны сквозь геометрию; рамка выделения захватывает и скрытые элементы. Повторное нажатие возвращает обычный вид. X-Ray влияет только на отображение модели: материалы GLB, сцена и история правок сохраняются.

Каждая вкладка модели имеет собственную историю Ctrl+Z / Ctrl+Shift+Z и хранит несохранённые правки при переключении. **Ctrl+S перезаписывает сам GLB**; сцены, использующие этот ассет, получают обновлённую модель. До сохранения правки меша существуют только в его вкладке. Контейнер сохраняет материалы, текстуры и дополнительные данные; временный файл заменяет исходный после успешной записи, а внешние изменения GLB блокируют сохранение. При закрытии изменённой вкладки можно сохранить, отбросить правки или отменить закрытие.

При открытии модели и добавлении примитивов совместимые соседние треугольники автоматически объединяются в четырёхугольные грани, в том числе после перемещения отдельных вершин куба. У куба доступны шесть целых граней без диагоналей; выделение, выдавливание и разрезы работают с ними целиком. Границы материалов, швы UV и заданные нормали сохраняются. Структура полигонов записывается в дополнительные данные GLB: после сохранения и открытия четырёхугольники и многоугольники остаются целыми, а явно выполненная триангуляция сохраняется как треугольники.

Редактирование поддерживает статические треугольные меши GLB 2.0 до 250 000 вершин и файлы до 512 МБ. Модели со скинингом, morph targets, внешними буферами геометрии или исходным сдвигом матрицы (shear) открываются для просмотра с объяснением ограничения. Есть отдельный UV-режим с автоматической развёрткой и правкой островов; стек модификаторов Blender, скульптинг, риггинг и анимационный редактор пока не реализованы.

В режиме **«Рисование»** можно рисовать кистью по 3D-модели или её текстуре в соседнем 2D-виде. B — кисть, E — ластик, I — пипетка; на левой панели есть заливка полигона. Справа находятся слои: добавление краски и заливки, копирование, удаление, видимость, порядок и непрозрачность. Ctrl+Z / Ctrl+Shift+Z отменяют и повторяют мазки и изменения слоёв. **«Сохранить» / Ctrl+S** записывает итоговый материал и редактируемые слои внутрь GLB; после повторного открытия работа со слоями продолжается. Нужна UV-развёртка; текущее разрешение — 1024 × 1024. Окружение и управление камерой остаются такими же, как в редакторе модели. Подробнее о переносе Material Painter и оставшихся возможностях: [описание интеграции](docs/material-painter-migration.md).

Если перенос отдельного файла нарушил бы относительные ссылки glTF на текстуры или буферы, редактор отменит его: переносите модель вместе с зависимостями в общей папке.

Изображения PNG, JPEG, WebP, BMP, TGA, GIF, ICO и SVG отображаются миниатюрами; шахматный фон показывает прозрачность. Папки, модели, сцены, изображения и остальные файлы отображаются вместе в общем списке. Поиск работает внутри текущей папки и её подпапок. Двойной щелчок по карточке открывает изображение во вкладке верхней панели рядом со сценами и моделями. Масштаб и положение картинки сохраняются при переключении вкладок; файловый менеджер остаётся доступен. Клавиши ← / → переключают картинки из текущей папки или результатов поиска. Колесо меняет масштаб вокруг курсора, перетаскивание перемещает увеличенную картинку. F / 0 вписывает изображение в окно, клавиша 1 показывает пиксели в исходном масштабе с учётом DPI; двойной клик переключает эти режимы. Кнопка фона (B) меняет шахматный, тёмный и светлый фон. Ctrl+W или крестик на вкладке закрывает изображение, сохраняя остальные вкладки, папку, поиск и прокрутку файлового менеджера. Esc сворачивает файловый менеджер. Изображения загружаются в фоне; повреждённый файл можно пропустить или загрузить повторно. Для GIF показывается первый кадр, для больших файлов размер текстуры просмотра ограничен 4096 px по каждой стороне; размеры в подписи относятся к оригиналу.

В левом верхнем углу изображения находится компактное меню «Просмотр / Редактирование», оформленное как переключатель режима модели. Новые вкладки открываются в режиме просмотра. Редактирование использует ядро PhotoCraft: кисть / карандаш (B), ластик (E), заливка (G), пипетка (I), перемещение слоя (V), рука (H / Пробел), выбор цвета HSV / RGB / HEX и палитру. Внизу левой панели расположены образцы основного и фонового цветов: нажатие открывает окно с новым и текущим цветом, «ОК» применяет выбор, «Отмена» / Esc сохраняет прежний. X меняет цвета местами, D возвращает чёрный и белый. Справа находится дерево слоёв с миниатюрами, группами и отдельными миниатюрами масок. Ctrl выделяет несколько слоёв, Shift — диапазон; перетаскивание меняет порядок и переносит слой в группу, Alt создаёт копию. Доступны все режимы смешивания PhotoCraft, отдельные непрозрачность и заливка, блокировки, цветовые метки, связи, растровые и векторные маски, обтравка, корректирующие слои, заливки, эффекты, смарт-объекты и смарт-фильтры. Кнопка с лупой открывает поиск и фильтры слоёв. Щелчок правой кнопкой по слою открывает его контекстное меню. «Свойства» открывает параметры выбранного слоя; нажатие на маску переключает рисование на неё. Содержимое смарт-объекта открывается с кнопкой возврата; Ctrl+S применяет вложенные изменения перед сохранением. Слои и стили можно копировать между вкладками. Ctrl+G / Ctrl+Shift+G группирует / разгруппировывает, Ctrl+J дублирует, Ctrl+E объединяет выделенные слои, F2 переименовывает, Delete удаляет. ПКМ по кнопке рисования открывает выбор кисти или карандаша; Shift+B переключает их, B возвращает последний выбранный инструмент. Кисть рисует со сглаживанием, карандаш рисует по пиксельной сетке без сглаживания, начиная с 1 px. Размеры кисти и карандаша запоминаются отдельно. Кисть и обычный ластик учитывают силу нажатия пера, если драйвер передаёт её через Windows Ink или WinTab: размер в панели задаёт максимальный диаметр. Для мыши и пиксельных инструментов размер остаётся фиксированным. Размер показан компактной кнопкой в верхней панели: колесо над ней меняет значение по пикселю, нажатие открывает библиотеку кистей с категориями и образцами мазков. У импортированных кистей фактура восстанавливается по образцу мазка из библиотеки Procreate. Щетина следует за движением пера, а повторяющаяся сетка привязана к холсту. Выбранный диаметр запоминается для каждой кисти до закрытия редактора. Для карандаша и ластика доступны ползунок и точный числовой ввод. На холсте Shift + движение мыши вправо/влево увеличивает/уменьшает диаметр без рисования; центр предпросмотра остаётся в точке начала жеста, рядом показан размер в пикселях. Esc отменяет такую настройку. Для карандаша и пиксельного ластика размер округляется до целых пикселей. Ctrl+Z отменяет действие; Ctrl+Shift+Z / Ctrl+Y повторяет. При первом включении редактирования рядом создаётся одноимённый `.pcraft` со структурой слоёв. Ctrl+S сохраняет слои и обновляет исходное изображение в прежнем формате. Повторное редактирование оригинала загружает слои из `.pcraft`. Закрытие вкладки или редактора с несохранёнными правками предлагает сохранить, продолжить без сохранения или отменить закрытие. Исходные изображения PNG, JPEG, WebP, BMP, TGA и ICO открываются для редактирования в 8-битном RGB; нативный `.pcraft` сохраняет сложные слои и их параметры. Ограничения документа: до 16 Мп и 4096 слоёв. Встроенные библиотеки и лицензии перечислены в `ATTRIBUTION.md`.

Слева на холсте при работе кистью, карандашом или ластиком находятся два вертикальных ползунка: верхний меняет размер, нижний — непрозрачность. Фон панели совпадает с панелью инструментов, по краю проходит тонкая золотистая обводка. Бегунки — простые серые закруглённые прямоугольники с мягкой реакцией на наведение; заполнение шкал приглушено и не анимируется. Крупные области захвата неподвижны. Бегунки перетаскиваются без скачка при захвате; движение вверх увеличивает значение. Шкала размера нелинейная для точной настройки маленьких кистей. Число появляется при наведении или перетаскивании. Размер и непрозрачность синхронизированы с меню кисти.

## Управление

Менеджер проектов и редактор используют общую верхнюю панель без системного заголовка окна. Перетаскивайте свободную область панели, дважды щёлкните её для разворачивания или восстановления размера; кнопки справа сворачивают, разворачивают и закрывают окно. Размер окна меняется за края и углы. Закрытие редактора по-прежнему предлагает сохранить несохранённые сцены.

Картинки можно перетащить из Проводника прямо в файловый менеджер — по одной или несколько сразу. Импорт создаёт копии в текущей папке либо в папке под курсором (дерево, карточка или путь сверху), а миниатюры появляются автоматически. Совпадающие имена получают суффикс «(2)», «(3)» и далее. ПКМ открывает меню «Создать папку»: на свободном месте — для текущей папки, на папке — внутри неё. Введите название и нажмите «Создать» или Enter; Esc отменяет ввод. Ctrl+Shift+N сразу открывает создание папки. Ошибки имени и совпадение с существующим файлом показываются прямо в диалоге.

Подсказки при наведении и клавиатурном фокусе объясняют действия и сочетания клавиш. Недоступные кнопки приглушены и пропускаются при переходе через Tab. Инспектор прокручивается, если все параметры не помещаются по высоте.

Ширина всех меню справа меняется перетаскиванием левой границы панели. Разделитель между деревом сцены и инспектором меняет их высоту. Выбранные размеры сохраняются при переключении объектов и сцен; после временного уменьшения окна они восстанавливаются. Esc отменяет перетаскивание. Разделители также доступны через Tab: стрелки меняют размер, Shift задаёт меньший шаг, Home возвращает автоматический размер.

Выбранный объект выделяется тонкими оранжевыми уголками по границам всей модели в 3D-виде. Объёмная рамка следует повороту и масштабу объекта и видна сквозь остальные объекты. Цветные оси позволяют перемещать, вращать и масштабировать выделение. По умолчанию включён режим со стрелкой (Q) для выбора объектов. Перемещение, поворот и масштабирование включаются отдельными инструментами W, E и R. В режимах W/E/R клики в 3D-виде сохраняют текущее выделение. В дереве сцены можно выбирать объекты, открывать меню по ПКМ и удалять их при любом активном инструменте. У стрелок перемещения заполненные наконечники, у масштаба — заполненные объёмные кубики; у всех трёх инструментов есть белая точка в центре. Манипулятор вращения имеет постоянный размер на экране: три цветные передние полудуги и тонкое серое кольцо для вращения в плоскости экрана. При захвате форма дуг сохраняется, активная ось подсвечивается. В миниатюрах и превью камер уголки не отображаются.

«+ Свет» открывает меню создания: точечный источник, прожектор, солнце и прямоугольная панель. Есть отдельные пресеты лампочки, свечи, софтбокса, неона, прожектора, солнца и луны, а также схемы дневного света, тёплого интерьера, ночи и студии. Схема заменяет только добавленные в редакторе светильники и общие настройки освещения одним отменяемым действием. Источники выбираются в дереве или по значку в 3D-виде; их можно перемещать, поворачивать, переименовывать, дублировать и отключать. Цвет источника, фонового света и тумана выбирается на двумерной палитре насыщенности и яркости; полоса под ней меняет оттенок. Рядом показаны образец и HEX-код цвета. Температура в Кельвинах, мощность в люменах (для солнца — люксы), яркость фона, экспозиция, дальность, радиус, углы прожектора и размеры панели меняются ползунками с немедленным результатом в сцене. Одно перетаскивание отменяется целиком через Ctrl+Z, а Esc возвращает значение до начала перетаскивания. Расширенные параметры теней раскрываются отдельно. Панели в текущей версии Bevy не отбрасывают тени.

Строка «Освещение сцены» в дереве открывает фоновый свет, экспозицию EV100, тональное отображение, туман, качество теней и переключатель источников из исходного GLB. Эти настройки, добавленные светильники и история отмены независимы для каждой вкладки. Превью камер, миниатюры сцен и сохранённые документы учитывают изменения; Esc закрывает меню, Ctrl+Z отменяет правку.

В разделе HDRI выбирается одно из десяти окружений Poly Haven: студии, склад, интерьер, облачное небо, закаты, лес или ночь. Выбранная панорама видна вдали за сценой, освещает объекты и отражается на материалах с учётом их шероховатости. Яркость HDRI и поворот вокруг вертикальной оси меняются ползунками; фон поворачивается вместе с освещением. Переключатель «Панорама на фоне» позволяет скрыть картинку, сохранив свет и отражения. «Выкл.» отключает окружение, сохраняя значения ползунков. Настройки сохраняются в сцене, поддерживают отмену и используются в превью камеры и миниатюрах сцен. Карты встроены в приложение, загружаются асинхронно и разделяются между камерами; копировать их в каждый проект не требуется. Исходные панорамы и подготовленные карты имеют [лицензию CC0](assets/hdri/LICENSE.txt). Повторная подготовка на Rust: `cargo run --locked --release --manifest-path tools/prepare-hdri/Cargo.toml -- --source path/to/hdri`; Python не нужен. Параметры и проверки описаны в [инструкции инструмента](tools/prepare-hdri/README.md).

Кнопка «Скачать HDRI…» в настройках освещения открывает каталоги [Poly Haven](https://polyhaven.com/hdris) и [ambientCG](https://ambientcg.com/list?type=HDRI). В окне есть превью, поиск по названию и тегам, страницы каталога и выбор 1K/2K/4K. «Скачать» показывает ход загрузки и позволяет её отменить; после завершения карта попадает во вкладку «Скачанные» и список окружений в инспекторе. Кнопка «Использовать» применяет её к сцене с поддержкой отмены. HDR и EXR из ZIP ambientCG подготавливаются для фона, освещения и отражений в фоне; Python и ручная конвертация не нужны. Панорамы, источник и лицензия хранятся внутри `asset_root/hdri`, поэтому скачанные окружения работают без интернета и переносятся вместе с проектом. Каталоги и превью кешируются в `asset_root/.bevy-editor/hdri-catalog`; «Обновить» запрашивает свежие данные. Выбор окружения, его поворот, яркость и видимость панорамы сохраняются в сцене.

Числовые поля принимают точку и запятую как десятичный разделитель. Ошибочное значение остаётся в поле с подсветкой и объяснением; его нужно исправить или отменить через Esc перед сохранением, сменой сцены и закрытием окна.

История хранит до 64 действий. Незавершённое перетаскивание отменяется по Esc. При закрытии изменённой вкладки или окна с несохранёнными изменениями появляется выбор: сохранить, продолжить без сохранения или отменить переход. Ошибка сохранения оставляет диалог открытым и сохраняет правки в памяти. При выходе проверяются все открытые сцены, включая неактивные вкладки. Запуск игры требует сохранить изменения. Кнопка «Играть» появляется, если у сцены задан `play` — программа и массив аргументов, без командной оболочки. `program: null` запускает текущий исполняемый файл. Рабочий каталог и относительный путь программы следуют правилам `std::process::Command`.

Движение из вида камеры меняет её позу в текущей сцене. Один жест навигации отменяется целиком через Ctrl+Z; Ctrl+S записывает текущий ракурс в файл. Выход из вида камеры сохраняет её изменения в памяти и возвращает прежний свободный вид редактора. Превью и вид из камеры используют одинаковый кадр 16:9.

## Диалоги и персонажи

В контекстном меню файлового менеджера категория **Диалоги → Диалог / Персонаж** создаёт `.dialog` и `.dcharacter` в выбранной папке ассетов. Эти документы открываются в общей панели вкладок; у каждого своя история изменений и индикатор несохранённых правок.

Имя персонажа и название диалога задают имя соответствующего файла. После короткой паузы в наборе файл, вкладка и карточка в файловом менеджере переименовываются автоматически; расширение сохраняется. Если имя занято, к имени файла добавляется числовой суффикс. Ссылки на персонажа в сохранённых диалогах и открытых документах обновляются вместе с файлом. Некорректное имя подсвечивается под полем; отмена правок возвращает прежнее имя.

Диалог редактируется прямо в нодах, без правой панели. В **Начале** задаётся название диалога; текст ответа для стартового перехода не нужен. В реплике задаются говорящий, портрет, текст и варианты ответа. Поле **Кто говорит** открывает выпадающий список рядом с нодой: поиск фильтрует персонажей по имени и пути файла, **↑ / ↓** перемещают выбор, **Enter** применяет его, **Esc** или щелчок снаружи закрывает список. Точка выхода находится в строке ответа справа от крестика, без отдельной кнопки и дополнительной строки. Для соединения перетащите её ко входу слева в заголовке другой ноды. Линия следует за мышью, подходящий вход подсвечивается. **Esc** или отпускание в пустом месте отменяет действие и сохраняет прежнюю связь. С клавиатуры можно активировать выход, затем вход; панель выбора также позволяет создать продолжение или выбрать ноду из списка. Заголовок перемещает саму ноду. **+ Вариант ответа** добавляет ветку. ПКМ по точке выхода или **Delete** на точке с клавиатурным фокусом разрывает связь. Команда **Разорвать** также доступна после щелчка по точке. Крестик у ответа удаляет сам ответ. Новые ноды размещаются рядом с исходной. Циклы допустимы, а предпросмотр сообщает о незавершённых переходах.

Создание нод сопровождается коротким появлением и свечением контура. Новая связь прорисовывается импульсом от выхода ко входу; разорванная линия и удалённая нода растворяются. Эффекты учитывают масштаб и перемещение графа, работают при отмене/повторе и автоматически убираются при переключении вкладок. Они не меняют документ и не перехватывают ввод.

Рядом с текстом реплики и подписью завершения кнопка **Редактор** открывает большой редактор текста. Размер шрифта, полужирное и курсивное начертание, подчёркивание, зачёркивание и цвет применяются только к выделенному фрагменту. Выделение сохраняется при работе с панелью инструментов и палитрой. Кнопка цвета открывает общую с редактором изображений палитру HSV/RGB/HEX и образцы; ОК применяет цвет, Отмена оставляет прежний. Выравнивание и межстрочный интервал настраиваются для реплики. Есть поиск и замена с учётом регистра, списки, буфер обмена, счётчики и отдельная история правок. **Применить / Ctrl+Enter** переносит черновик в ноду одним действием отмены; **Ctrl+S** также сохраняет файл. **Отмена** оставляет исходный текст. При закрытии окна с изменённым черновиком редактор предлагает применить, отменить или продолжить редактирование. Оформление хранится в необязательных полях `text_format` (основной стиль и абзац) и `text_spans` (стили фрагментов по UTF-8 диапазонам) документа `.dialog` и используется в предпросмотре; старые файлы открываются с обычным оформлением.

В `.dcharacter` имя, описание и портреты редактируются на центральной странице досье. Подпись эмоции, выбор основного портрета и удаление находятся на карточке изображения. Страница прокручивается целиком и сохраняет положение при действиях с портретами; поля сохраняют фокус при наборе и изменении размера окна. Изображения вписываются в рамку без искажения пропорций. В каждой реплике выбирается персонаж и нужный портрет. **Проверить** запускает интерактивный предпросмотр всех веток без сохранения документа.

Перетаскивайте заголовки для перемещения узлов, удерживайте среднюю или правую кнопку мыши для перемещения графа, используйте колесо для масштаба и **F** для показа всего графа. **Ctrl+S** сохраняет документ, **Ctrl+Z / Ctrl+Shift+Z** отменяет и повторяет изменения, **Ctrl+W** закрывает текущую вкладку, **Esc** отменяет соединение или закрывает предпросмотр. Форматы — JSON версии 1; ссылки на персонажей и изображения задаются относительно папки ассетов.

## Подключение к игре

Добавьте репозиторий как Git submodule и подключите пакет по локальному пути:

```sh
git submodule add git@github.com:L4legenda/bevy-editor.git modules/bevy-editor
```

```toml
[features]
editor = ["bevy-editor/editor"]

[dependencies]
bevy-editor = { path = "modules/bevy-editor", default-features = false }
```

Без фичи `editor` доступны формат уровней и функции инстанцирования; фича `game` добавляет самостоятельный игровой запуск. Интерфейс редактора и миниатюры подключаются только к инструменту разработки. Для клонирования игры используйте `git clone --recurse-submodules` или `git submodule update --init --recursive`.

В отдельном исполняемом файле редактора:

```rust,no_run
use bevy_editor::{EditorProject, create_app};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let project = EditorProject::load("project.json")?;
    create_app(project)?.run();
    Ok(())
}
```

`EditorProject` также можно собрать в Rust. `scene_setup` и `camera_setup` позволяют применить материалы, свет и эффекты игры. Свои плагины добавляются в возвращённый `App` до `run()`. Для полностью своего приложения доступен `EditorPlugin::new(project)`; добавляйте его после `DefaultPlugins`, отключив стандартное закрытие окна через `WindowPlugin::close_when_requested`.

В собственном нативном приложении добавьте `AssetRedirectPlugin::new(asset_root)?` **до** `DefaultPlugins`, чтобы загрузка через `AssetServer` поддерживала сохранённые перемещения. `create_app` уже подключает этот плагин. Обработчики `scene_setup` и `camera_setup` получают исходные логические пути сцен.

## Формат сцены и runtime

Кнопка **▶ Запустить** / **F5** запускает открытый уровень в отдельном окне Bevy с текущими несохранёнными изменениями. Во время игры она превращается в **■ Остановить**. Фича `game` предоставляет готовую основу Bevy без UI редактора: `runtime::GameLevelPlugin`, `create_game_app`, игровую камеру и экземпляры моделей со стабильными ID. [Запуск уровня и подключение собственной игры](docs/play-mode.md).

Файл `.scene` использует JSON. Поле `scene` содержит название и определения камер; остальные поля описывают содержимое:

* `scene` — `label` и список `cameras` с ID, подписью, проекцией и исходной позой;

* `nodes` — поддерживается только для совместимости с правками прежних GLB-сцен; новые сцены используют `models`;
* `cameras` — позы и объективы камер по стабильным ID;
* `models` — ID экземпляра, относительный путь общего GLB или FBX, поза и необязательный локальный AABB для коллизии.
* `lights` — источники света со стабильными ID, типом, позой, цветом, мощностью и настройками теней;
* `lighting` — общие настройки освещения и камеры. Отсутствующее поле сохраняет исходное освещение хоста.

Сохранение проверяет данные и заменяет файл через временный файл в том же каталоге. Дублирование создаёт новый ID и сохраняет ссылку на тот же ассет. Меши и текстуры загружаются через общий `AssetServer`.

```rust,no_run
use std::path::Path;
use bevy_editor::LevelEdits;

let edits = LevelEdits::<String>::read(Path::new("assets"), "scenes/workshop.scene");
```

`LevelEdits<K>` поддерживает и сериализуемый enum камер игры. Его snake_case ключи совместимы со строковыми ID редактора. `runtime::imported_nodes` находит редактируемые объекты, `runtime::spawn_model` создаёт экземпляры. Runtime игры применяет мировую позу узла через `GlobalTransform::reparented_to` и использует `anchor` / `seat_yaw` для связанных игровых точек. Система коллизий принадлежит хосту; `solid` сохраняет геометрические границы модели для его использования. Запуск доступен через встроенную основу Bevy или внешнюю команду `play`.

Для применения света в игре подключите фичу `lighting` у зависимости `bevy-editor`. `lighting::spawn_light` / `runtime::spawn_lights` создают сохранённые источники; `lighting::apply_camera_lighting` применяет окружение к игровой камере после настроек хоста, а `lighting::apply_imported_light` — переключатели к исходным светильникам. DTO и чтение JSON доступны без этой фичи. В `Clinic-of-desires-bevy` сохранённое освещение уже подключено к обычному запуску игры.

Для встроенных HDRI добавьте `bevy_editor::HdriPlugin` после `DefaultPlugins`, затем применяйте сохранённый `SceneLighting` через `apply_camera_lighting`. Редактор подключает плагин автоматически. В редакторе для сцен без сохранённых настроек освещения по умолчанию включено HDRI «Облачно» с панорамой на фоне, тёплым заполняющим светом и мягкой светлой картинкой (экспозиция 8 EV100, Reinhard Luminance, яркость HDRI 1300). Новые проекты сохраняют эти настройки в стартовой сцене и используют HDRI без дополнительного яркого солнца. Сохранённые окружения и явное «Выкл.» имеют приоритет. При чтении старых DTO в игре прежняя семантика отсутствующих настроек сохраняется.

Редактор поддерживает расстановку объектов, камер и освещения в сценах, а также отдельные вкладки полигонального редактирования статических GLB-моделей. Материалы, скрипты, риги и анимации создаются в исходных инструментах.

## Готовые сборки Windows

GitHub Actions автоматически собирает `bevy-editor.exe` для Windows x64 в режиме `--release`:

| Push в ветку | Публикация на GitHub | Пример тега |
| --- | --- | --- |
| `main` | Обычный Release с пометкой Latest | `v0.1.0+build.42.1.abcdef12` |
| `develop` | Pre-release с отдельным тегом | `develop-42.1-abcdef12` |

В тег входят номер запуска workflow, номер попытки и первые восемь символов коммита. Для `main` добавляется версия из `Cargo.toml`. Повторный запуск создаёт новый тег; предыдущие сборки сохраняются. Сборки `develop` не получают пометку Latest.

Скачайте `bevy-editor.exe` из [Releases](https://github.com/L4legenda/bevy-editor/releases) и запустите его: откроется менеджер проектов. Rust и Cargo для готовой сборки не нужны. Шрифт, иконки и HDRI встроены в приложение. Существующий проект можно открыть командой `bevy-editor.exe --project PATH`.

Workflow [Windows releases](.github/workflows/windows-release.yml) должен быть в обеих ветках. Он также поддерживает ручной запуск через **Actions → Windows releases → Run workflow** для `main` и `develop`. Публикация использует встроенный `GITHUB_TOKEN` с разрешением `contents: write`; отдельный секрет не нужен. Версия Rust берётся из `package.rust-version` в `Cargo.toml`.

Тесты проверяют перезапись и совместимость документов с типизированными камерами, отклонение некорректных ссылок, общие ассеты при дублировании, историю изменений, ограничения трансформаций и переход между сценами с разным числом объектов. Тестовый код компилируется только в тестах.

Встроенный шрифт Liberation Sans распространяется по [SIL Open Font License](assets/font/OFL.txt).

SVG-иконки интерфейса — [Lucide](https://lucide.dev/icons), с [лицензиями ISC и MIT](assets/icons/lucide/LICENSE). Исходники находятся в `assets/icons/lucide/` и встроены в редактор; чёткие текстуры создаются и кэшируются под масштаб экрана.
