# MCP в Bevy Editor

Редактор предоставляет Model Context Protocol для работы с открытым проектом из MCP-клиента. Поддерживаются Streamable HTTP и отдельный stdio-мост `bevy-editor-mcp`. Реализация использует [официальный Rust SDK MCP](https://github.com/modelcontextprotocol/rust-sdk).

## Подключение

Соберите оба исполняемых файла через `cargo build --locked --bins` и откройте нужный проект в редакторе. MCP запускается автоматически с фичей `mcp`, которая включена по умолчанию.

В настройках MCP-клиента добавьте stdio-сервер с абсолютными путями к мосту и проекту:

```json
{
  "mcpServers": {
    "bevy-editor": {
      "command": "C:/path/to/bevy-editor/target/debug/bevy-editor-mcp.exe",
      "args": ["--project", "C:/path/to/project/project.bevyeditor"]
    }
  }
}
```

В Linux/macOS файл называется `bevy-editor-mcp`, без `.exe`. `--project` принимает папку вашего проекта или его манифест `project.bevyeditor`.

Мост подключается к уже открытому проекту. После перезапуска редактора переподключите MCP-клиент: адрес и ключ сессии меняются. Stdout моста содержит только MCP-сообщения, ошибки идут в stderr.

Для прямого Streamable HTTP-подключения поля `url` и `token` находятся в `<папка ассетов>/.bevy-editor/mcp.json`. Передавайте `token` как Bearer-токен. Сервер слушает только `127.0.0.1` на свободном порту и проверяет токен, Host и Origin. Файл подключения исключён из Git и удаляется при штатном закрытии своего экземпляра редактора.

## Инструменты

| Инструмент | Действие |
| --- | --- |
| `get_editor_state` | Активная сцена, готовность, выделение, несохранённые правки, Undo/Redo и положение вида |
| `list_scenes` / `open_scene` | Просмотр и открытие сцен с сохранением правок остальных вкладок в памяти |
| `list_objects` | Объекты активной сцены, их ID, трансформации и разрешённые оси |
| `list_assets` | Доступные модели проекта |
| `get_paint_state` | Открытая 3D-модель, наборы текстур, слои и маски активного набора, настройки кисти и состояние запекания |
| `open_paint_model` | Открыть GLB из каталога в режиме «Рисование» |
| `replace_paint_mesh` | Заменить геометрию с переносом слоёв, отменить или повторить замену |
| `list_paint_presets` | Каналы, доступные материалы, генераторы, наконечники, режимы смешивания и заливки, качество запекания и шаблоны экспорта |
| `edit_paint` | Выбор набора и слоя, создание, настройка, перемещение и удаление слоёв, маски, генераторы, фильтры и история рисования |
| `paint_stroke` | Мазок кистью или ластиком на слое либо маске в 3D-виде или на UV-плитке |
| `poly_fill` | Заливка по выбранной грани, поверхности, UV-острову или другому режиму полигональной заливки |
| `select_surface` | Записать связную часть модели или поверхность до сгиба в маску слоя |
| `save_model` | Запись открытой модели в GLB с редактируемыми слоями или создание копии под новым именем |
| `export_textures` | Экспорт готовых карт активного или всех наборов с возвратом путей к записанным файлам |
| `bake_maps` | Запуск запекания карт для активного набора текстур |
| `get_bake_state` / `cancel_bake` | Отчёт о прогрессе и картах выбранного набора, отмена запекания этого набора |
| `set_paint_view` | Камера, раскладка, просмотр канала или карты запекания, трассировка и экспозиция |
| `cage_preview` | Показ оболочки проекции и отчёт о попаданиях лучей |
| `capture_paint_view` | PNG изображения, которое сейчас показывает 3D-вид рисования |
| `select_object` | Выбор объекта в дереве и инспекторе |
| `set_transform` | Атомарное изменение позиции, поворота и/или масштаба с одним шагом Undo |
| `add_model` | Добавление экземпляра GLB или FBX из каталога проекта |
| `add_light` / `set_light` | Создание света из пресета и настройка цвета, мощности, дальности, температуры, теней, имени и включения |
| `remove_object` | Отменяемое удаление добавленной модели или источника света |
| `set_visibility` | Локальная сохраняемая настройка видимости объекта |
| `set_view` | Позиция свободного вида редактора и точка, на которую он смотрит |
| `capture_viewport` | Свежий PNG 3D-вида размером до 1600×1000 |
| `save_scene` | Проверка и сохранение сцены обычным механизмом редактора |
| `undo` / `redo` | Общая с интерфейсом история изменений |

Также доступны ресурсы `bevy-editor://state`, `bevy-editor://scenes` и `bevy-editor://objects`. Последний содержит первые 100 объектов; для остальных используйте `list_objects` с `offset` и `limit` (1–250). Та же пагинация доступна у `list_assets`.

Передайте точный путь из `list_assets` в `open_paint_model`, например `{"asset":"models/block.glb"}`. Команда возвращает `model_id` и статус `opening`. Повторяйте `get_paint_state` с `{}` после ответа о загрузке, пока результат для этого `model_id` не покажет режим `paint` и доступную кисть. Команда использует уже открытую вкладку модели и сохраняет её правки при переключении.

Индексы наборов и слоёв начинаются с нуля. `layers_bottom_to_top` идёт в порядке смешивания, `folder` указывает индекс родительской группы, `udim` содержит номер плитки или `null`. В режиме «Рисование» `get_paint_state` возвращает текущие правки, настройки кисти и историю активного набора. В других режимах доступны сохранённые в документе слои, а `brush` равен `null`. `list_paint_presets` доступен без открытой модели. Обе команды чтения работают через HTTP и stdio.

`replace_paint_mesh` принимает текущие `model_id` и `active_set` в объекте `workspace`. Передайте `active_set` как `set`. Пример замены на примитив.

```json
{
  "workspace": {"model_id": 0, "set": 0},
  "replacement": {"kind": "primitive", "shape": "rounded_cube"}
}
```

Доступные формы — `rounded_cube`, `sphere`, `torus`, `cylinder`, `plane` и `material_ball`. Для файла используйте `{"kind":"file","path":"models/replacement.obj"}`. Поддерживаются OBJ и FBX, абсолютные пути и пути относительно папки ассетов. Для отмены и повтора передайте `{"kind":"undo"}` или `{"kind":"redo"}`. Команда отвечает после изменения геометрии. При замене результат содержит число перенесённых и несопоставленных наборов текстур. После каждого изменения перечитайте `get_paint_state`, чтобы получить актуальные индексы и доступность отмены.

В режиме «Рисование» передайте `model_id` и `active_set` из результата `get_paint_state` как `model_id` и `set` запроса `edit_paint`. Необязательная `revision` позволяет проверить, что набор и индексы слоёв ещё соответствуют полученному состоянию.

```json
{
  "model_id": 0,
  "set": 1,
  "edit": { "operation": "update_layer", "index": 0, "name": "Патина", "opacity_percent": 65 }
}
```

`edit_paint` возвращает обновлённое состояние. `update_layer` принимает также `visible` и `blend` и объединяет переданные свойства в один шаг отмены. Для перемещения используйте `move_layer` с `from`, `to` и `placement` (`above`, `below` или `inside`). `set_mask` создаёт белую или чёрную маску (`white` или `black`) либо удаляет её (`remove`). Для отмены и повтора правок рисования используйте операции `undo` и `redo` команды `edit_paint`.

Обе команды рисования принимают `workspace` с `model_id`, `set` и необязательной `revision`. В `target` передайте индекс `layer`, `space` (`viewport` или `uv`) и `mask: true`, если правите маску. Координаты идут слева направо и сверху вниз от 0 до 1. В `viewport` они относятся к текущему 3D-виду, в `uv` — ко всей активной плитке независимо от её масштаба и прокрутки.

```json
{
  "workspace": { "model_id": 0, "set": 0 },
  "target": { "layer": 0, "space": "uv" },
  "samples": [{ "position": [0.35, 0.5] }, { "position": [0.65, 0.5], "pressure": 0.8 }],
  "brush": { "size_px": 24, "channels": { "base_color": [190, 110, 70], "roughness": 128 } }
}
```

Для `poly_fill` вместо `samples` передайте `position` и, при необходимости, `mode` из `list_paint_presets`. Пропущенные параметры кисти берутся из редактора. В `brush` можно задать `size_px`, `hardness_percent`, `flow_percent`, `opacity_percent`, `spacing_percent`, `erase`, `mask_value` или `channels`. Значения каналов и маски задаются байтами 0–255. Явно указанные каналы ограничивают мазок этим набором каналов. Команды ставят работу в GPU-очередь. Перед следующей правкой дождитесь `paint_busy: false` через `get_paint_state`. Если мазок попал вне геометрии или ничего не изменил, шаг отмены не появляется.

`select_surface` использует `workspace` и индекс видимого слоя `layer`. Для `source` выберите `{"kind":"parts","indices":[0]}`, `{"kind":"point","position":[0,0,0]}` в мировых координатах или `{"kind":"viewport","position":[0.5,0.5]}` с нормализованными координатами 3D-вида. Части нумеруются с нуля по порядку появления в видимой геометрии. При выборе точки выделение растёт через общие рёбра, включая швы UV. `crease_angle` задаётся в градусах от 1 до 179, по умолчанию 30. `stop_at: "concave"` останавливается на вогнутых сгибах, а `"any"` на всех сгибах, превышающих угол.

`mode` принимает `replace`, `add` или `subtract`. Команда записывает результат в UV-плитку активного набора и создаёт маску, если её ещё нет. Вся правка занимает один шаг отмены. После `paint_busy: false` поле `surface_selection` в `get_paint_state` содержит число выбранных треугольников, число треугольников активного набора, мировые границы или сообщение об ошибке.

После завершения мазка передайте `model_id` в `save_model`. Чтобы создать копию рядом с исходным файлом, добавьте `copy_name`, например `Патина.glb`. Имя должно быть свободно. Ответ содержит путь к записанному файлу.

`export_textures` принимает `model_id` и `folder`. Укажите существующую абсолютную папку или путь от каталога ассетов проекта. Экспорт создаёт отдельную подпапку и возвращает `folder` и `files` после записи. По умолчанию экспортируется текущий набор. `all_sets: true` экспортирует все наборы с сохранением номеров UDIM. Дополнительные поля `template`, `format`, `bit_depth`, `size`, `padding`, `padding_width` и `prefix` переопределяют настройки одного экспорта. Экспорт учитывает текущие правки в памяти, поэтому его можно запустить до записи исходного GLB.

Передайте в `bake_maps` объект `target` с `model_id` и, при необходимости, `set` активного набора. Запекание использует его разрешение. Например, параметры `"quality": "draft"` и `"maps": ["occlusion", "curvature"]` выбирают профиль и дополнительные карты для запекания. Доступные идентификаторы возвращает `list_paint_presets`. Для проекции укажите `high_poly` и при необходимости `cage` абсолютным путём или путём от каталога ассетов. Пустой путь сбрасывает ранее выбранный файл. Параметр `preview: true` открывает вкладку «Карты» с предпросмотром.

Вызывайте `get_bake_state` с `model_id` и `set` до статуса `ready`, `failed` или `cancelled`. Отчёт включает прогресс от 0 до 1, готовые карты, покрытие UV и статистику попаданий лучей. `cancel_bake` принимает тот же запрос и отменяет только задачу указанной модели и набора.

`set_paint_view` принимает `model_id` и нужные поля камеры: `center`, `distance`, `yaw_degrees`, `pitch_degrees`, `fov_degrees` и `orthographic`. Поле `layout` выбирает `split`, `three` или `two`. С помощью `preview` можно показать материал (`{"mode":"material"}`), канал (`{"mode":"channel","channel":"roughness"}`) или карту (`{"mode":"baked","map":"occlusion"}`). `path_trace` включает трассировку, а `exposure_stops` задаёт экспозицию от −5 до 3 ступеней. Результат возвращает состояние камеры.

Чтобы проверить оболочку, укажите `high_poly` через `bake_maps`, затем вызовите `cage_preview` с `model_id` и `show: true`. Без поля `show` команда читает отчёт. Когда `report.status` равен `ready`, доступны числа попаданий, результатов на пределе, промахов и пересечений с другими частями. `show: false` скрывает оболочку.

`capture_paint_view` принимает `model_id` и возвращает PNG до 1600×1000 пикселей. Команда снимает текущую картинку из 3D-вида, в том числе результат трассировки или диагностику модели. В режиме только UV сначала включите `layout: "three"` или `layout: "split"`.

## Пример

Вызовите `get_editor_state`, дождитесь `ready: true` и получите `list_objects` с `{}`. Используйте полученный `id` целиком в `set_transform`:

```json
{
  "object_id": "scenes/workshop.scene::model:1",
  "transform": {
    "position": [2, 0.5, -1],
    "rotation_degrees": [0, 45, 0]
  }
}
```

Позиция задаётся в мировых метрах. Поворот соответствует инспектору: X — наклон, Y — курс, Z — крен, в градусах. Пропущенные свойства сохраняются. Заблокированные оси и недопустимые значения отклоняются целиком, без частичного изменения объекта. ID включает сцену, поэтому ID из другой вкладки не изменит одноимённый объект в активной сцене. После `open_scene` дождитесь загрузки и снова получите ID.

Правки сцены остаются в памяти до `save_scene` и входят в ту же историю, что и действия мышью. `set_view` меняет только вид редактора. `capture_viewport` снимает цель активной камеры вместе с DPI-масштабом окна, поэтому масштаб интерфейса 125–200% не требует менять параметры запроса. `set_visibility` сохраняет отдельную локальную настройку видимости. Встроенные объекты исходного GLB можно скрывать, но нельзя удалять через `remove_object`.

Во время перетаскивания, незавершённого ввода или диалога подтверждения команды изменения возвращают объяснение; чтение остаётся доступным. Отменённые и просроченные запросы не применяются позже из очереди. Если геометрия добавленной модели ещё загружается, повторите `save_scene` после её готовности.

## Встраивание и проверка

В приложении с `EditorPlugin` добавьте `bevy_editor::mcp::McpPlugin` после него. Сеть обслуживается отдельным потоком, изменения сцены выполняются в основном потоке Bevy. Входящий запрос пробуждает оконный цикл для работы с фоновым окном.

Фича `mcp` включает `editor` и не нужна игровому runtime. Минимальная зависимость игры по-прежнему использует `default-features = false`. Сборка редактора без MCP: `cargo build --locked --no-default-features --features editor --bin bevy-editor`.

```sh
cargo test --locked --lib editor::mcp
cargo check --locked --no-default-features
```

GPU-регрессия захвата 3D-вида при масштабе 200% и после изменения ракурса:

```sh
cargo test --locked --lib gpu_mcp_capture_renders_the_viewport_at_high_dpi -- --ignored --test-threads=1
```

PNG проверки сохраняются во временный каталог `bevy-editor-mcp-capture`; переменная `BEVY_EDITOR_TEST_OUTPUT_DIR` задаёт другую папку.

Сквозной GPU-тест запускает отдельный процесс stdio-моста для временной копии проекта. Он проверяет запекание, мазок, снимок 3D-вида и пиксели, записанные в GLB и PNG.

```sh
cargo build --locked --bin bevy-editor-mcp
cargo test --locked --lib gpu_stdio_paint_workflow_saves_and_exports -- --ignored --test-threads=1
```

Если мост собран в другой папке, задайте путь к нему через `BEVY_EDITOR_MCP_STDIO`.

Проверки охватывают подключение официального SDK по HTTP, инструменты и ресурсы, отменяемые правки, валидацию, заблокированные оси, сохранение с геометрией моделей, просроченные запросы, активный ввод и защиту локального подключения.
