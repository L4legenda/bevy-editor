# MCP в Bevy Editor

Редактор предоставляет Model Context Protocol для работы с открытым проектом из MCP-клиента. Поддерживаются Streamable HTTP и отдельный stdio-мост `bevy-editor-mcp`. Реализация использует [официальный Rust SDK MCP](https://github.com/modelcontextprotocol/rust-sdk).

## Подключение

Соберите оба исполняемых файла через `cargo build --locked --bins` и откройте нужный проект в редакторе. MCP запускается автоматически с фичей `mcp`, которая включена по умолчанию.

В настройках MCP-клиента добавьте stdio-сервер с абсолютными путями к мосту и проекту:

```json
{
  "mcpServers": {
    "bevy-editor": {
      "command": "C:/path/to/bevy-editor/target/debug/bevy-editor-mcp.exe",
      "args": ["--project", "C:/path/to/project/project.bevyeditor"]
    }
  }
}
```

В Linux/macOS файл называется `bevy-editor-mcp`, без `.exe`. `--project` принимает папку проекта или его манифест. Для встроенного примера укажите абсолютный путь к `examples/project.json`.

Мост подключается к уже открытому проекту. После перезапуска редактора переподключите MCP-клиент: адрес и ключ сессии меняются. Stdout моста содержит только MCP-сообщения, ошибки идут в stderr.

Для прямого Streamable HTTP-подключения поля `url` и `token` находятся в `<папка ассетов>/.bevy-editor/mcp.json`. Передавайте `token` как Bearer-токен. Сервер слушает только `127.0.0.1` на свободном порту и проверяет токен, Host и Origin. Файл подключения исключён из Git и удаляется при штатном закрытии своего экземпляра редактора.

## Инструменты

| Инструмент | Действие |
| --- | --- |
| `get_editor_state` | Активная сцена, готовность, выделение, несохранённые правки, Undo/Redo и положение вида |
| `list_scenes` / `open_scene` | Просмотр и открытие сцен с сохранением правок остальных вкладок в памяти |
| `list_objects` | Объекты активной сцены, их ID, трансформации и разрешённые оси |
| `list_assets` | Доступные модели проекта |
| `select_object` | Выбор объекта в дереве и инспекторе |
| `set_transform` | Атомарное изменение позиции, поворота и/или масштаба с одним шагом Undo |
| `add_model` | Добавление экземпляра GLB из каталога проекта |
| `add_light` / `set_light` | Создание света из пресета и настройка цвета, мощности, дальности, температуры, теней, имени и включения |
| `remove_object` | Отменяемое удаление добавленной модели или источника света |
| `set_visibility` | Локальная сохраняемая настройка видимости объекта |
| `set_view` | Позиция свободного вида редактора и точка, на которую он смотрит |
| `capture_viewport` | Свежий PNG 3D-вида размером до 1600×1000 |
| `save_scene` | Проверка и сохранение сцены обычным механизмом редактора |
| `undo` / `redo` | Общая с интерфейсом история изменений |

Также доступны ресурсы `bevy-editor://state`, `bevy-editor://scenes` и `bevy-editor://objects`. Последний содержит первые 100 объектов; для остальных используйте `list_objects` с `offset` и `limit` (1–250). Та же пагинация доступна у `list_assets`.

## Пример

Вызовите `get_editor_state`, дождитесь `ready: true` и получите `list_objects` с `{}`. Используйте полученный `id` целиком в `set_transform`:

```json
{
  "object_id": "scenes/workshop.scene::model:1",
  "transform": {
    "position": [2, 0.5, -1],
    "rotation_degrees": [0, 45, 0]
  }
}
```

Позиция задаётся в мировых метрах. Поворот соответствует инспектору: X — наклон, Y — курс, Z — крен, в градусах. Пропущенные свойства сохраняются. Заблокированные оси и недопустимые значения отклоняются целиком, без частичного изменения объекта. ID включает сцену, поэтому ID из другой вкладки не изменит одноимённый объект в активной сцене. После `open_scene` дождитесь загрузки и снова получите ID.

Правки сцены остаются в памяти до `save_scene` и входят в ту же историю, что и действия мышью. `set_view` меняет только вид редактора. `set_visibility` сохраняет отдельную локальную настройку видимости. Встроенные объекты исходного GLB можно скрывать, но нельзя удалять через `remove_object`.

Во время перетаскивания, незавершённого ввода или диалога подтверждения команды изменения возвращают объяснение; чтение остаётся доступным. Отменённые и просроченные запросы не применяются позже из очереди. Если геометрия добавленной модели ещё загружается, повторите `save_scene` после её готовности.

## Встраивание и проверка

В приложении с `EditorPlugin` добавьте `bevy_editor::mcp::McpPlugin` после него. Сеть обслуживается отдельным потоком, изменения сцены выполняются в основном потоке Bevy. Входящий запрос пробуждает оконный цикл для работы с фоновым окном.

Фича `mcp` включает `editor` и не нужна игровому runtime. Минимальная зависимость игры по-прежнему использует `default-features = false`. Сборка редактора без MCP: `cargo build --locked --no-default-features --features editor --bin bevy-editor`.

```sh
cargo test --locked --lib editor::mcp
cargo check --locked --no-default-features
```

Проверки охватывают подключение официального SDK по HTTP, инструменты и ресурсы, отменяемые правки, валидацию, заблокированные оси, сохранение с геометрией моделей, просроченные запросы, активный ввод и защиту локального подключения.
