# Формат сцен версии 1

Формат реализован в `crates/scene-format`. Он не зависит от Bevy, Godot или
редактора и описывает только авторские данные. Редактируемый `.scene` — UTF-8
JSON с постоянными идентификаторами. Производный `.sceneb` — индексированные
бинарные таблицы, при необходимости сжатые LZ4. Для Git хранится `.scene`;
бинарный файл можно пересоздать из исходников и зависимостей.

Измерения и выводы о TSCN находятся в [отчёте](scene-format-audit.md).

## Исходный документ

```json
{
  "format":"bevy_scene",
  "version":1,
  "id":"c5cad6ad-c6a8-43e1-90a4-568e0d22e4c9",
  "name":"Комната",
  "settings":{},
  "resources":{
    "chair":{"kind":"model","path":"models/chair.glb"}
  },
  "entities":[
    {"id":"chair_01","name":"Стул","model":"chair","transform":{"translation":[1.0,0.0,2.0]}}
  ]
}
```

- `id` документа — ненулевой UUID. Переименование и перенос файла сохраняют
  UUID. Копирование в файловом менеджере редактора создаёт новый UUID.
- `resources` — таблица ресурсов с постоянными локальными ключами. Изменение
  пути не требует перенумеровывать ссылки на ресурс.
- `entities` — записи сущностей с постоянными строковыми ID. Имя и родитель
  могут меняться независимо от ID. ID исходной сущности не содержит `/`.
- `parent` ссылается на ID, `order` задаёт порядок среди соседей. Положение записи
  в JSON не определяет иерархию или порядок соседей.
- `settings` содержит настройки всей сцены, например `environment`. Настройки
  вложенного документа не заменяют настройки родительской сцены; настройки
  отдельного объекта следует хранить в его компонентах.

Позиции задаются в метрах, вращение — кватернионом `[x,y,z,w]`, масштаб — тремя
числами. Редактор использует ось Y вверх. Отсутствующая трансформация означает
нулевую позицию, единичный кватернион и единичный масштаб. Эти значения закреплены
за версией формата и не зависят от текущих стандартных настроек движка.

Каноническая запись сортирует ресурсы и сущности по ID, разделяет свойства и
поля компонентов по строкам и записывает массивы чисел в строку. Изменение позиции
обычно меняет одну строку; изменение имени и изменение позиции занимают разные
строки и легче объединяются в Git. Запись `instance` пока остаётся компактным
объектом, поэтому разные переопределения одного экземпляра могут конфликтовать
при слиянии. Переформатированный пользователем валидный JSON также
принимается; комментарии JSON не поддерживаются.

## Ресурсы и компоненты

Ресурс содержит `kind` и ровно один источник: `path` или `data`. Необязательные
поля — `uid`, `selector`, `sharing`. Пути относительны корню ассетов, используют
`/` и не содержат `..`, абсолютных путей, `\\`, `:` или `#`. Подресурс указывается
через `selector`, например `Scene0`, отдельно от пути.

`uid` позволяет загрузчику проекта разрешать ресурс независимо от пути. Сам
кодек не сканирует диск и не создаёт глобальный реестр ассетов. Интерфейс
`SceneLoader` позволяет подключить такой реестр. CLI использует пути; текущий
редактор также сохраняет свою систему перенаправлений перемещённых ассетов.
Нельзя считать наличие поля UID автоматической защитой от любого переноса файла.

`sharing: "shared"` — стандартная политика общего ресурса; `"local"` требует
локальной копии при создании экземпляра. Для встроенных ресурсов резолвер
формирует устойчивый UID из UUID документа и ключа ресурса. Два экземпляра сцены
сохраняют общий источник такого материала. Реальное кеширование GPU-ресурсов
и создание локальных копий выполняет загрузчик/движок согласно этой политике.

`components` — словарь имени компонента и JSON-данных. Неизвестные компоненты
сохраняются. Значение `null` остаётся значением. Внутри данных зарезервированы
однополевые ссылки `{"$entity":"id"}` и `{"$resource":"key"}`. Обычная строка
с похожим содержимым не считается ссылкой и не переписывается автоматически.
Типы игровых компонентов должны иметь собственную версию схемы, например
`game.Interaction.v1`: версия контейнера не фиксирует значения стандартных полей
неизвестного игрового компонента.

Дублированные ID, ключи компонентов и вложенные ключи JSON отклоняются. Неизвестные
поля структур самого формата отклоняются, чтобы новая схема не была молча потеряна
старым редактором. Для расширений используются компоненты и настройки сцены.

## Вложенные сцены и переопределения

```json
{"id":"lamp_01","instance":{"resource":"lamp","overrides":{"bulb":{"components":{"light":{"intensity":1600}}}}}}
```

`lamp` — внешний ресурс `kind: "scene"`. Запись экземпляра становится точкой
подключения; корни вложенной сцены становятся её детьми. После разрешения
экземпляра ID `bulb` получает область имён `lamp_01/bulb`. Внутренние типизированные
ссылки переназначаются в ту же область. Обычные имена и пути объектов не служат ID.

Переопределение адресует ID внутри экземпляра. Оно может изменить имя,
трансформацию, модель, заменить компонент целиком, удалить модель или явно
перечисленные компоненты. `remove: true` удаляет сущность с её поддеревом.
Поверхностного или рекурсивного слияния произвольных JSON-объектов нет: смысл
замены компонента не зависит от состава новой версии исходного объекта.
`remove_components` отличается от присваивания `null`.

Сначала применяются изменения вложенной сцены, затем внешнего экземпляра.
Отсутствующий адресат, конфликт удаления/изменения, оборванная ссылка, цикл
родителей или сцены отклоняются. Исходные документы не изменяются. Загрузчик
кеширует документ на время одного разрешения; повторные экземпляры не требуют
повторно читать тот же локатор. Лимиты ограничивают количество сущностей,
ресурсов, глубину вложения и объём развёрнутых данных.

Рабочий пример композиции без запуска пользовательского кода находится в
`examples/scene-format/room.scene` и `lamp.scene`.

## Бинарное представление

Все целые и `f32` имеют порядок байтов little-endian. Layout Rust/C и указатели
не сериализуются. В реализации нет `unsafe` или `transmute`.

| Смещение заголовка | Содержимое |
|---:|---|
| 0 | Magic `BSCN\r\n\x1a\n`, 8 байт |
| 8 | Версия, `u32` |
| 12 | Размер заголовка: 128, `u32` |
| 16 | Полный размер: `u64` |
| 24 | BLAKE3 fingerprint авторских данных и транзитивных сцен, 32 байта |
| 56 | BLAKE3 всего файла, кроме самого поля контрольной суммы, 32 байта |
| 88 | Количество сущностей, `u32` |
| 92 | Количество ресурсов, `u32` |
| 96 | Размер пула строк, `u32` |
| 100 | Размер пула блоков данных, `u32` |
| 104, 108, 112, 116 | Смещения сущностей, ресурсов, строк и блоков, `u32` |
| 120, 124 | Смещение и размер блока метаданных внутри пула блоков |

Запись сущности занимает 80 байт: диапазоны ID и имени, индексы родителя и
модели, порядок, резерв, 10 чисел трансформации и диапазон компонентов.
Родитель всегда предшествует ребёнку. `u32::MAX` означает отсутствие родителя
или модели. Запись ресурса занимает 32 байта: диапазоны ключа, типа, пути и
дополнительных данных. Диапазон задаётся парой `(offset, length)` из `u32`.

Разрешённая сцена исключает неиспользуемые ресурсы, сохраняя транзитивное замыкание
типизированных ссылок. Исходный авторский документ при этом не меняется.
Строки и идентичные блоки компонентов интернируются. Встроенные компоненты
сохраняют JSON-представление, но читаются только по запросу. Общие поля доступны
как заимствованные срезы; полный разбор JSON и создание `String` для каждой
сущности не нужны. Проверка уникальности ID использует временную память.
`unpack()` создаёт полноценные изменяемые структуры и ожидаемо стоит дороже,
чем получение представления таблиц.

Проверяются размеры, границы секций, контрольная сумма, UTF-8, индексы, ID,
резерв и трансформации. JSON внутри блоков проверяется при запросе соответствующих
данных или при `unpack()`. Контрольная сумма обнаруживает повреждения и не является
криптографической подписью доверенного автора.

Сжатый контейнер начинается с `BSCZ\r\n\x1a\n`. За magic следуют версия,
исходный размер, размер сжатого блока и нулевой резерв (`u32`, заголовок 24 байта).
Далее расположен LZ4 block. Распаковка ограничена размером и допустимым расширением,
после неё выполняется обычная проверка BSCN. Сжатый файл требует буфера распаковки;
для непосредственного произвольного доступа выбирается несжатый вариант.

## Лимиты и запись

- Исходник — до 64 MiB; бинарный файл — до 512 MiB.
- До 1 000 000 сущностей и 100 000 ресурсов.
- До 64 вложенных сцен и 64 уровней данных компонента.
- Стандартный бюджет развёрнутого текста — 128 MiB; можно уменьшить через
  `ResolveLimits`. Это ограничение оценки данных, а не обещание пикового RSS.
- Иерархия сущностей обрабатывается итеративно; тест включает цепочку из 20 000
  родителей. Глубина иерархии не равна глубине включения файлов.

`SourceDocument` запоминает хеш прочитанного файла и отклоняет сохранение после
внешнего изменения. `atomic_write` пишет во временный файл рядом с исходником,
синхронизирует его и заменяет исходник. Согласованные писатели используют OS-lock;
авария процесса освобождает блокировку. Сам lock-файл сохраняется в локальной
`.bevy-editor/scene-locks`, чтобы не создавать гонку разных inode.
Проверка revision оптимистическая: сторонняя программа, не использующая lock,
теоретически может вмешаться между последней проверкой и заменой файла. Гарантия
полной транзакции с любым внешним редактором не заявляется.

## Интеграция и воспроизведение

Обычное сохранение новых и существующих `.scene` в редакторе использует версию 1.
Прежние `.scene` читаются без перезаписи и мигрируют при сохранении; прежние JSON
правок остаются прежним форматом. UUID, неизвестные компоненты и неизвестные
настройки сохраняются. Перенос ассетов меняет таблицу ресурсов с сохранением её
ключей; копирование сцены создаёт новый UUID.

Редактор отображает авторскую иерархию, группы и вложенные сцены в дереве.
Инспектор поддерживает родителя, локальные координаты и переопределения экземпляра;
подробности — в [руководстве](scene-hierarchy-editor.md). История и открытые вкладки
хранят исходный граф и общие неизменяемые снимки зависимостей. Сохранение не
уплощает документ. Камера обзора для префаба без камер существует только в редакторе.

Модели и свет создаются под настоящими родителями Bevy как в редакторе, так и
в миниатюрах и `GameLevelPlugin`. Это сохраняет affine-трансформации, включая shear
при сочетании вращения и неравномерного масштаба. Runtime API без `editor` читает
иерархические `.scene` и `.sceneb`; запуск игры передаёт снимок зависимостей.
Произвольные игровые компоненты сохраняются в данных, но автоматически в ECS
не регистрируются. Модели по-прежнему загружаются как GLB `Scene0`.

```powershell
cargo test --manifest-path crates/scene-format/Cargo.toml
cargo clippy --manifest-path crates/scene-format/Cargo.toml --all-targets -- -D warnings
cargo test --no-default-features --test documents
cargo test --no-default-features --test hierarchy
cargo test --lib scene_hierarchy
cargo run --release --manifest-path crates/scene-format/Cargo.toml --bin scene-format -- cook examples/scene-format room.scene target/room.sceneb --lz4
cargo run --release --manifest-path crates/scene-format/Cargo.toml --bin scene-format -- inspect target/room.sceneb
cargo run --release --manifest-path crates/scene-format/Cargo.toml --bin scene-format -- bench target/scene-format-audit/rust-benchmarks.json
```

Компилятор намеренно не загружает геометрию, текстуры и пользовательские скрипты.
Проверка импортированных ассетов и их собственные кеши относятся к загрузчику
ресурсов. Изменение транзитивной сцены меняет fingerprint; изменение содержимого
внешнего GLB при неизменной ссылке не требует перекодировать таблицу ссылок сцены.
