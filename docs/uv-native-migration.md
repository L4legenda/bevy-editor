# Перенос UV на Rust + C++

Проверка: 16 ноября 2026, Windows x64. UV работает встроенным нативным процессором без Python, pip, uv, CUDA и загрузки пакетов. Старые Python-файлы UV удалены; Python-компоненты других инструментов редактора не затрагиваются.

## Что перенесено

Подготовка неманифолдных рёбер и построение дерева Ward выполняются на Rust. PartUV Geometric/ABF и упаковщик xatlas вызываются непосредственно из C++ через C ABI. Сохранены параметры качества, размера и отступов, работа в фоне, отмена, просмотр 3D/UV, шахматная текстура, швы, сравнение, выделение и преобразования островов, повторная упаковка, Undo/Redo и сохранение GLB.

Исполняемый файл процессора и OpenMP DLL встроены в редактор. C/C++ runtime процессора статически слинкован. Проверка PE показала только VCOMP140.DLL и системные библиотеки Windows; VCOMP140.DLL входит во встроенный комплект. Заголовки C++ поставляются в проекте и проверяются по SHA-256.

## Сравнение на том же персонаже

Использована локальная модель `character.glb` из прежнего теста PartUV Geometric, 23 755 треугольников. Модель не добавлена в репозиторий. GPU-тест работает с временной копией.

Для численного сравнения старый и новый процессоры получили один и тот же JSON, полученный из геометрии документа редактора: `target/uv-qa/native-character-request.json`. Старый интерпретатор запускался только как эталон при этой проверке. Новый процессор и редактор к нему не обращаются.

| Метрика | Прежний Python-адаптер | Rust + C++ |
| --- | ---: | ---: |
| Треугольники | 23 755 | 23 755 |
| Острова по ответу движка | 136 | 136 |
| Суммарная площадь UV | 24,3423% | 28,2034% |
| Угловое искажение p50 | 1,018053 | 1,018063 |
| Угловое искажение p95 | 1,059264629 | 1,059264629 |
| Нормализованное растяжение p95 | 1,1257667 | 1,1257754 |
| Длина швов, единицы модели | 36,4382 | 36,4174 |
| Грани за пределами 0–1 | 0 | 0 |

Угловое искажение — отношение сингулярных чисел UV-преобразования; 1 означает отсутствие углового искажения. Квантили взвешены по площади поверхности. Площадь UV — сумма площадей треугольников, а не самостоятельная проверка перекрытий.

Искажения практически сохранились. Дополнительный поиск размещения повысил UV-площадь примерно на 15,9% относительно эталона на точном входе редактора. Форма островов и крайне узкие углы защищены восстановлением единого преобразования острова.

Отдельно на исходном входе прежнего бенчмарка Rust и Python дали совершенно одинаковые подготовленные позиции, треугольники и все 23 754 слияния дерева Ward. На этом входе UV-площадь составила 26,0854% у эталона и 27,8537% у нового движка; различие входов учитывается, результаты двух сравнений не смешиваются.

## Выполненные проверки

- Rust-тесты подготовки геометрии: 2 пройдены.
- Проверки редактора по фильтру `uv_`: 13 пройдены, отдельный GPU-тест запущен явно.
- Встроенный комплект разворачивается в пустую папку и выполняет расчёт с PATH, содержащим только Windows System32, без Python-переменных среды.
- Отмена останавливает уже начавшийся нативный расчёт; вызов отмены занимает менее 200 мс.
- Упаковка тестовой карты с узким треугольником сохраняет относительные расстояния внутри каждого острова с допуском 0,1%.
- Полный GPU-тест на персонаже пройден: авторазвёртка, сравнение, выделение, перемещение, Undo/Redo, отмена, упаковка, сохранение GLB. Проектная сцена и её история не изменились.
- Сохранённый GLB повторно открыт независимым Rust-декодером glTF: 23 755 треугольников, все 12 334 уникальные позиции и площадь поверхности совпали с исходником; координаты UV конечны и находятся в 0–1.
- `cargo build --locked --offline --bin bevy-editor -j4` завершился успешно. Готовый редактор: `target/debug/bevy-editor.exe`.

Артефакты проверки находятся в `target/uv-native-qa`: `editor-native-tests.log`, `native-unit-tests.log`, `editor-gpu-native.log`, `editor-native-build.log`, `gui-quality.json`, `tree-parity.json`, `saved-glb-verification.json`, `native-pe-dependencies.txt`. Скриншоты — в `target/uv-qa`.
