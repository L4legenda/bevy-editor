# Запуск уровня в Bevy

Кнопка **▶ Запустить** в верхней панели и **F5** открывают текущий уровень в отдельном окне Bevy. При запуске используется снимок сцены: добавленные модели, преобразования и удаления объектов, камеры и освещение, включая несохранённые изменения. Файл уровня при встроенном запуске не перезаписывается.

Если в редакторе выбрана камера, запуск использует её. Иначе используется первая камера уровня. Свободный вид редактора не заменяет игровую камеру.

Во время запуска кнопка меняется на **■ Остановить**. Повторное нажатие завершает принадлежащий редактору игровой процесс. Закрытие игрового окна или **Esc** также завершает запуск; можно продолжить редактирование. При закрытии редактора запущенная им игра останавливается.

Встроенная основа содержит загрузку уровня, рендеринг и свободную камеру: **ПКМ + мышь** — осмотр, **WASD** — движение, **Q / E** — вниз / вверх, **Shift** — ускорение. Игровые правила, персонаж и физика добавляются отдельными Bevy-системами.

## Собственная игра

Для игрового приложения доступна возможность `game` без интерфейса редактора:

```toml
bevy-editor = { path = "../bevy-editor", default-features = false, features = ["game"] }
```

`runtime::GameLevelPlugin` загружает уровень в существующий `App`, а `runtime::create_game_app` создаёт готовый `App` с окном и управлением камерой. Компоненты `GameCamera` и `GameModel(id)` позволяют находить камеру и экземпляры объектов из своих систем. `GameLevelStatus` сообщает о готовности уровня и ошибках загрузки. Для собственного управления камерой используйте `GameLevelPlugin` вместо `create_game_app`.

Для самостоятельного запуска сохранённой сцены без редактора:

```rust,no_run
use bevy_editor::runtime::{GameLevel, create_game_app};

let level = GameLevel::read("assets", "scenes/main.scene")?;
create_game_app("assets", level)?.run();
# Ok::<(), std::io::Error>(())
```

Существующая настройка `play` у сцены продолжает запускать внешнюю программу. Перед таким запуском редактор сохраняет изменённый уровень, чтобы прежние игровые приложения получили актуальные данные. Программа дополнительно получает переменные окружения:

- `BEVY_EDITOR_LEVEL` — относительный путь открытого уровня;
- `BEVY_EDITOR_ASSET_ROOT` — абсолютный путь к ассетам;
- `BEVY_EDITOR_PLAY_SNAPSHOT` — путь к временному JSON со снимком уровня.

Пример точки входа собственного игрового приложения:

```rust,no_run
use bevy_editor::runtime::{GameLaunch, create_game_app};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let launch = GameLaunch::read(std::env::var("BEVY_EDITOR_PLAY_SNAPSHOT")?)?;
    let mut app = create_game_app(launch.asset_root, launch.level)?;
    // app.add_plugins(MyGameplayPlugin);
    app.run();
    Ok(())
}
```

Временный снимок доступен на протяжении игрового сеанса и удаляется после завершения процесса. Для ручного воспроизведения снимка используется `bevy-editor --play-snapshot PATH`.

## Игровой GLB

Откройте модель и нажмите **Игровой GLB…** на панели просмотрщика. Экспорт записывает отдельный файл и учитывает текущие правки геометрии и материала. Сохраняются готовые PBR-текстуры, UV, анимации, скелеты и морф-цели. Исходный GLB остаётся редактируемым со слоями, масками и настройками запекания.

Редактор удаляет свои данные из копии, исключает неиспользуемые записи и уплотняет бинарный буфер GLB. Для неизвестных расширений и дополнительных блоков сохраняются исходные индексы и смещения, поэтому такие файлы могут уменьшаться меньше. GLB с внешними ресурсами сохраняйте в ту же папку, чтобы относительные ссылки продолжили работать.
